# CarPal MVP — Social Web UI Screen List (Car Owner)

**App:** CarPal consumer web app (PWA) and public pages, Next.js with server-side rendering for public pages (Plan WP19, `pwa/`).
**Users:** guests (not signed in) who arrive from search engines or shared links, and signed-in car owners such as Sara, who "sometimes uses the PWA on her laptop" ([10.User Story - Car Owner](10.User%20Story%20-%20Car%20Owner.md)).
**Builds on:** [21.Mobile_app_screen_list](21.Mobile_app_screen_list.md) (element-level specs for shared screens), [56.UI-UX Social Flow](56.UI-UX%20Social%20Flow.md) (feed, composer, engagement rules), [90.CarPal Screen Map](90.CarPal%20Screen%20Map.md).
**Admin side:** [23.Admin_WebUI_screens](23.Admin_WebUI_screens.md).

**Scope of this document**
- **Public and social pages** are specified in full: landing, public provider and vendor profiles, directory pages, posts, Q&A, member pages, feed, composer, notifications.
- **Signed-in tools** (garage, Help Me, appointments, reviews, settings) use the same elements as the mobile screens in Doc 21. For those, this document specifies only the **web layout, the web-specific elements and the web-specific interactions**, and refers to the Doc 21 screen for the element list.

**How to read each screen:** Purpose · Access (guest / signed-in) · Route · Layout · Elements · Interactions · States · SEO and sharing (public pages) · Story chapter.

**Screen IDs:** this document uses the prefix **`W-`** for web screens. Each web screen names the mobile screen it mirrors ("Mirrors `C-PROV-01`"). The `W-` prefix is new and is listed in §8 for WP0 approval.

## 1. Web experience principles

| # | Principle | What it means on the web |
| :--- | :--- | :--- |
| 1 | **Public by default, private by design** | Provider/vendor profiles, showcases and Q&A are readable without an account. Garage, appointments, documents and personal data never are. |
| 2 | **Intent survives sign-in** | When a guest clicks Follow, Request appointment, Helpful or Comment, the auth modal opens and, after sign-in, the action completes on the same page. The user never lands on a generic home page. |
| 3 | **Use the space** | Desktop shows the list and the detail side by side (master–detail), so users compare without going back and forth. |
| 4 | **Same trust language as mobile** | Badges, verified marks, match explanations, "Featured" labels and AI labels look and read the same on web and mobile (Doc 21 §2.3). |
| 5 | **Fast first view** | Public pages render on the server. Main content is visible within 2.5 s on a mid-range phone on 4G (Largest Contentful Paint target). |
| 6 | **Keyboard first on desktop** | Everything works by keyboard; visible focus; `/` focuses search; `Esc` closes modals. |
| 7 | **Shareable and indexable** | Every public page has a clean URL, title, description and a preview image for link sharing. Private pages are never indexed. |
| 8 | **RTL and LTR equal** | `dir="rtl"` for Persian with logical CSS properties; language in the URL (`/fa/…`, `/en/…`) so search engines index both. |

## 2. Layout system

### 2.1 Breakpoints

| Width | Layout | Navigation |
| :--- | :--- | :--- |
| < 768 px (mobile web) | One column, same patterns as the mobile app (Doc 21). | Bottom tab bar (signed in) or top bar with menu (guest). |
| 768–1199 px (tablet) | Two columns: main + one rail; master–detail collapses to list → detail pages. | Collapsible left navigation (icons only). |
| ≥ 1200 px (desktop) | Three columns: left navigation (240 px), main content (max 680 px for feeds, wider for tools), right rail (320 px). Tools use master–detail. | Full left navigation with labels. |

### 2.2 Global header (all pages)

| Element | Guest | Signed in |
| :--- | :--- | :--- |
| Logo | Links to `W-PUB-01` | Links to `W-FEED-01` (home) |
| Search box | Yes. `/` shortcut. Opens a dropdown with suggestions (Doc 21 `S-SHARED-01`), accepts text in any supported language, and has a **Browse on map** link. | Same, plus the vehicle context chip inside the box ("for Silver · BMW 320i"). |
| **Help Me** button | Yes (opens `W-HELP-01`; asks to sign in at the vehicle step, or continue without an account with limited matching) | Yes, primary colour |
| Language switch | FA / EN | In avatar menu |
| Notifications bell | — | Unread count; opens a dropdown panel (`W-NOTIF-01`) |
| Avatar menu | **Log in** / **Sign up** buttons instead | Profile, My activity, Saved, Settings, Switch account, Log out |

### 2.3 Left navigation (signed in, desktop)

Home (feed) · Discover (search, with a **Browse on map** link) · My Garage · Help Me · Appointments · Community Q&A · Saved · Notifications · Settings. A small "Your garage" box under the navigation shows the active vehicle with a quick switch, and one line of status ("1 open issue").

### 2.4 Right rail (feed and public pages)

Context-aware boxes, max three at a time:
- Signed in: **Your car** (active vehicle, next reminder, open issue with **Find help**), **Needs your attention** (proposed time, review invitation, showcase consent), **Shops to follow** (based on vehicle and location).
- Guest: **Join CarPal** card (value + Sign up), **Top specialists near you**, **Popular questions**.
- Featured placements are reserved and **off in the MVP** (flag `featured.enabled`). When enabled they appear only in a box labelled "Featured", never inside lists (MVP Rule 2) and never on the map.

### 2.5 Global web patterns

| Pattern | Rule |
| :--- | :--- |
| **Auth modal** (`W-AUTH-01`) | Opens over the page for gated actions. Remembers the action and completes it after sign-in. |
| **Modals vs. pages** | Short tasks (compose post, report, filters on tablet) use modals with a URL that can be refreshed. Long tasks (Help Me, review, add vehicle) are pages. |
| **Toast with Undo** | For reversible actions, bottom-start corner, 5 s. |
| **Drag and drop** | All upload areas accept drag and drop and paste (Ctrl+V) of images. |
| **Hover cards** | Hovering an author or provider name for 500 ms shows a card with rating, badges and Follow. Not used on touch. |
| **Infinite scroll with anchors** | Feeds load more on scroll; the back button returns to the same scroll position. A "Back to top" button appears after 3 screens. |
| **Print** | Service history and pre-visit report have print-friendly layouts. |
| **PWA install** | After the second signed-in visit, a small "Install CarPal" prompt appears in the header (dismissible, not repeated for 30 days). Web push is asked only after a user action that benefits from it (e.g. sending an appointment request). |
| **Cookie and tracking consent** | First visit shows a banner with **Accept all**, **Reject non-essential**, **Choose**. Equal prominence for accept and reject. |

**Purpose:** explain CarPal in five seconds and get the visitor to either a useful search or sign-up.
**Access:** guest (signed-in users are redirected to `W-FEED-01`). **Route:** `/fa`, `/en`.

**Layout (top to bottom)**

| Section | Elements | Behaviour |
| :--- | :--- | :--- |
| Hero | Headline: "Find the right trusted expert for your exact vehicle and problem — not just the nearest shop." Two inputs side by side: **Your car** (brand → model → series picker, or VIN) and **What's wrong / what do you need?**. Button **Find specialists**. Secondary links **Describe a problem with Help Me** and **Browse on map**. | Search works without an account, accepts text in any supported language, and opens `W-SRCH-01` with vehicle context. |
| How it works | 3 steps with icons: Add your car → Describe the problem → Get matched with proof. | — |
| Trust explained | "Why our badges mean something": Verified Business, Specialist (earned from completed jobs, not paid), Verified visit reviews. Link to a "How ranking works" page. | Builds the main differentiator: no paid ranking. |
| Popular specialists near you | 4–6 provider cards for the detected city (IP-based, editable "Near: Tehran ▾"). | Links to `W-PUB-02`. |
| Recent showcases | Before/after cards. | Links to `W-PUB-05`. |
| For businesses | Short block: "Run a repair shop or sell parts?" → business sign-up (portal). | — |
| Footer | About, How ranking works, Privacy, Terms, Help, language switch, app store links. | — |

**States:** location unknown (city picker shown as the first field); no providers in city ("We're launching in Tehran first" + notify-me sign-up).
**SEO:** title and description per language; Organization structured data; `hreflang` links between `/fa` and `/en`.
**Story:** Ch. 1 (a colleague's recommendation; the visitor arrives here or at a shared profile).

**Purpose:** same account flows as mobile (Doc 21 `S-AUTH-02`, `S-AUTH-03`, `S-AUTH-07`, `S-AUTH-08`, `S-AUTH-09`), on the web.
**Forms:** modal (640 px) when opened from a gated action; full page at `/login` and `/signup` otherwise.

| Element | Behaviour |
| :--- | :--- |

### W-ONB-01 — Web Onboarding

**Purpose:** the same onboarding as mobile, on one page with steps.
**Layout:** a centred card (max 720 px) with a step bar: **1. How you'll use CarPal** (`S-AUTH-04`) → **2. Your first car** (`C-ONB-01`) → **3. Anything wrong?** (`C-ONB-02`) → **4. Your interests** (`C-ONB-03`, optional) → **5. Permissions** (web version of `S-AUTH-05`).
**Web-specific:**
- VIN can be pasted; "Scan VIN" is replaced by **Continue on your phone** (QR code that opens the app at the same step).
- Permissions step asks only for what the browser supports: location (for "near me") and web push (offered as "Get appointment updates in your browser"). Photo access is not needed on the web.
- Business choices in step 1 open the business portal sign-up in the same tab, keeping the account.
**Interactions:** each step saves on **Next**; **Skip** is available on steps 2–5; leaving and returning resumes at the same step.
**Story:** Ch. 1, 2.

### W-PUB-02 — Public Provider Profile

**Purpose:** the shop's public trust page. It must convince a visitor from Google that this shop is the right expert, and turn that into a request.
**Mirrors:** `C-PROV-01` (all tabs and elements). **Access:** guest and signed in. **Route:** `/fa/shop/reza-auto-suspension-tehran` (slug + city).

**Desktop layout**

| Area | Elements |
| :--- | :--- |
| Header band (full width) | Cover image; logo; name; type; Verified Business badge; rating and count; area and distance (if location known); response time; price indicator; **Follow**, **Save** (heart), **Share** (copy link, WhatsApp, Telegram), overflow (Report). |
| Main column | Tabs as anchored sections on one page (Overview, Services & Capabilities, Portfolio, Reviews, Location & Hours, Q&A), with a sticky section menu. One long page is better for SEO and for scanning; the section menu highlights the current section on scroll. |
| Right rail (sticky) | **Request appointment** card: active vehicle chip (or "Select your car"), "Fit for your car" line (e.g. "BMW 3 Series (E90) · Suspension — Specialist · 19 jobs · ★4.8"), next available slots as buttons, primary **Request appointment**, secondary **Call** (reveals number on click, logged as a contact event). Below: a static map preview (the interactive map loads on click) and today's hours. |

**Section details (web additions to `C-PROV-01`)**
- **Overview:** review theme summary with the AI label; certifications with "Verified by CarPal" marks.
- **Services & Capabilities:** a matrix view on desktop (rows: brand/series; columns: service systems), each cell shows the evidence level as text and colour. Filter "Only my car". Self-declared capabilities in a separate, collapsed group.
- **Portfolio:** grid with category/model filters; opens `W-PUB-05` in a modal on desktop (URL updates, back closes the modal).
- **Reviews:** two-column: rating breakdown and sub-ratings on the left, filtered list on the right. Every published review carries one of two labels: **Verified visit** (written after a confirmed appointment) or **Approved by the business and CarPal** (no appointment, then confirmed); a disputed one adds "Disputed by the business". Both count in the score, the second for less. There is no separate unverified tab; a filter "Verified visit only" is available. Each review shows context ("Verified visit · BMW 3 Series · Suspension"), tags, shop reply, **Helpful** (sign-in required), **Report**. A **Write a review** button opens `W-REV-01`.
- **Location & Hours:** a light static map first, then the interactive map on click (keeps the page within the 2.5 s target); address with copy (or an approximate area if the shop chose that); **Get directions**, which opens the Directions menu (see `W-MAP-01`); a service radius circle for mobile mechanics (polygons come later).

**Interactions**

| User does | Guest | Signed in |
| :--- | :--- | :--- |
| Request appointment | Auth modal, then `W-HELP-01` at the request step with this provider | `W-HELP-01` request step (draft pre-filled) |
| Follow / Save / Helpful | Auth modal, then completes | Toggles immediately with toast and Undo |
| Clicks a badge | Popover: what it means, how it is earned | Same |
| Arrives from a Help Me match | — | "Why you're seeing this" box at the top of the main column |

**States:** verification pending (label instead of badge); no reviews; no portfolio; no availability (**Request anyway**); suspended or inactive (page shows notice, `noindex`, request disabled); merged duplicate (301 redirect to the surviving profile).
**SEO and sharing:** title "Reza Auto Suspension — BMW suspension specialist in Tehran | CarPal"; LocalBusiness / AutoRepair structured data with AggregateRating built from published reviews of both confirmation paths, using the same weighted score as the profile; preview image = cover or best showcase; canonical URL per language.
**Story:** Ch. 7.

### W-MAP-01 — Map View (full page) (new)

**Purpose:** browse shops and parts sellers on a large map, with the same results, filters, and explanations as the lists.
**Mirrors:** `S-SHARED-02` and `S-SHARED-10`. **Access:** guest and signed in. **Route:** `/fa/map` (not indexed).
**Entry points:** **Browse on map** (landing page hero, header search dropdown, Discover link in the left navigation), **Open full map** on `W-SRCH-01`, and the Location section of `W-PUB-02` and `W-PUB-03`.

**Desktop layout**

| Area | Elements |
| :--- | :--- |
| Top bar | Query field with query chips; vehicle chip; the **For [car]** filter button; layer chips **Shops** and **Parts sellers**; quick chip **Open now**; **Advanced search** (opens the filter panel). |
| Left (360 px) | The places in the current view as result cards, in the order of the current sort ("Sorted by closeness to the map centre" after **Search this area**). Hovering a card highlights its pin; clicking opens the card. |
| Centre | The map: shop and parts-seller pins with different shapes and icons, rank numbers 1–3 for the best matches, clusters, radius circles for mobile providers, a legend, zoom buttons, recenter. Dimmed pins are smaller and outlined, and remain clickable. |
| Selected pin | A popover and a highlighted card with **Request appointment** or **Ask about part**, **View**, and **Directions**. |

**Behaviour:** the same rules as `S-SHARED-02`. The vehicle filter is on when a car is chosen, and falls back to **Show all nearby** if fewer than 3 pins would remain. **Advanced search** highlights matching pins and dims the others, with a **Hide others** switch. Distances are straight-line and labelled "about". No trade prices, no private data, no featured pins. A guest picks a car from the list to use the vehicle filter.

**Directions on the web:** **Directions** opens a small menu built from the region's list of map apps (global and regional apps, an OpenStreetMap link, and a device map link on phones). ## 8. Open points (for WP0)

1. **`W-` prefix.** Doc 90 has no prefix for web-only consumer screens. This document adds `W-` and maps every web screen to its mobile screen. Approve or choose another convention.
2. **Guest Help Me.** This document lets guests run Help Me and see recommendations without an account (for SEO and conversion). Confirm this is acceptable for AI cost and abuse limits.
3. **Member pages.** Indexing of member pages is off by default for privacy. Confirm, and decide whether members can opt in.
4. **Repair stories with service records.** A repair story can show a linked service record summary. Define exactly which fields may be shown publicly (proposal: title, date, shop; never cost, mileage or VIN unless ticked).
5. **Tagged-shop approval.** Doc 56 §5.6 says a tagged provider "may show the post on their profile if approved". The provider-side approval screen belongs in the provider portal and is not specified yet.
6. **Directory pages.** City × category × brand pages need a rule for which combinations are generated, and a minimum result count (proposed: 3).
7. **Phone number reveal.** Clicking **Call** reveals the shop's number and logs a contact event. Confirm that shops want their number public, or only after sign-in.
8. **Navigation links on the web.** The Directions menu depends on the region's app list and the link formats of each app; some apps open only on devices where they are installed. Verify before building.
9. **Map loading budget.** The interactive map is loaded lazily on public pages. Confirm the 2.5 s target is measured without the map.
10. **Share preview without a map image.** Share previews use the cover image or best showcase, not a map image, because tiles are served as vectors.
11. **Review links on shared computers.** The email link needs a one-time code; confirm the code can also be sent by SMS for users without email access.
