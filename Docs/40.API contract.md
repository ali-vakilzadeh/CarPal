# CarPal MVP — API Contract

**Doc:** 40 · **Contract version:** 1.1.0 · **API major:** `v1` · **Date:** 2026-10-26
**Complies with:** [01.MVP_Plan.md](01.MVP_Plan.md), [02.Detailed project plan.md](02.Detailed%20project%20plan.md), [50.MVP data model spec.md](50.MVP%20data%20model%20spec.md), [51.MVP entity Relationship Map.md](51.MVP%20entity%20Relationship%20Map.md), [52.MVP Data Dictionary.md](52.MVP%20Data%20Dictionary.md).

**Authority.** This contract is the only interface between the clients (consumer mobile app, consumer PWA, provider/vendor/fleet portals, admin console) and the backend. Field names, types, enum values and validation come from 52; on a field conflict 52 wins and this document is corrected. On transport, operations, authorization and security, this document wins. The OpenAPI 3.1 file generated from NestJS (`shared/api-contracts/openapi.yaml`, Plan §14.1) must be equivalent to this contract; the CI contract check fails the build on any difference, and the router rejects any route that is not declared here (no shadow or undocumented endpoints).

**Machine-readability.** Every operation has a stable `op.id` heading, one descriptive paragraph, and a fixed-grammar block (§0.2). Every type is closed (`additionalProperties: false`). Security rules have stable IDs (`SEC-xx-n`) so tooling and tests can reference them.

# 0. Notation

## 0.1 Schema notation

Types are written in a TypeScript-like notation that maps 1:1 to JSON Schema 2020-12.

| Notation | Meaning |
|---|---|
| `type X = { a: T; b?: T }` | Closed object. `a` required, `b` optional (may be absent; `null` is not accepted unless written `T \| null`). |
| `// C: rule` | Conditional field (52 "C"). The rule says when it is required or forbidden. |
| `X & Meta` | Object `X` plus the response base fields (§3.2). |
| `A \| B` | One of. Objects in a union carry a discriminator field named in the type comment. |
| `T[]` / `List<T,n>` | Array / array with at most `n` items. `Set<T,n>` = array of unique items. |
| `'a' \| 'b'` or `EnumName` | Enum literal set / enum from the registry (§5). |
| `Partial<X>` / `Omit<X,'a'\|'b'>` | All fields of `X` optional / `X` without the named fields (same closed-object rule). |
| `X['field']` | The type of `field` in `X`. |
| `Json<Name>` | Object validated against the named server-side schema (listed in the OpenAPI components). |
| Response-only fields | Fields marked S in 52 appear only in response types. Sending them is `422 READ_ONLY_FIELD`. |

## 0.2 Operation block grammar

```
#### <op.id>
<one paragraph>
<METHOD> <PATH> -> <STATUS> <ResponseType>
in:   <RequestType> | -
q:    <name>: <Type>[=default], ...            (only when query parameters exist)
sec:  <TAG> <TAG>(<arg>) ...
err:  <STATUS> <CODE>[(detail)], ...            (operation-specific; common errors in §4.3 always apply)
emit: <domain.event>, ...                        (only when the operation publishes events)
```

|---|---|---|
| `{me}` | `/v1/me` | Caller's own user-private data |
| `{org}` | `/v1/orgs/{org_id}` | Caller must be an active member of `org_id` (SEC-AZ-2) |
| `{prv}` | `/v1/orgs/{org_id}/provider` | `org_id` type is `provider` or `hybrid_provider_vendor` |
| `{vnd}` | `/v1/orgs/{org_id}/vendor` | `org_id` type is `vendor` or `hybrid_provider_vendor` |
| `{flt}` | `/v1/orgs/{org_id}/fleet` | `org_id` type is `fleet` |
| `{pub}` | `/v1/public` | Public projections only |
| `{adm}` | `/v1/admin` on host `admin-api` only | Platform staff only (SEC-ADM) |
| `{V}` | `{me}/vehicles` **or** `{flt}/vehicles` | Vehicle owner scope: personal vehicles or fleet vehicles. The same operation exists under both prefixes. |

## 0.4 Security tags (`sec:` line)

| Tag | Meaning |
|---|---|
| `PUB` | No user needed. An anonymous client token (SEC-AU-14) or a user token is still required. |
| `PUB(no token)` | No token at all. Only the authorization server, discovery documents and `health.get`. |
| `USR` | Any authenticated user (aal1+). |
| `ORG(roles)` | Active membership in the path organization with one of the listed roles (role groups §0.5). |
| `DRV` | Fleet driver: allowed only on vehicles with an active `FleetVehicleAssignment` to the caller. |
| `STF(roles)` | Platform staff role on the admin plane (SEC-ADM). |
| `LNK(type)` | A link token of `type` (SEC-LT) is presented in the body; may be combined with `USR`. |
| `AAL2` / `AAL3` | Step-up: the session must have authenticated at that level within the last 10 minutes (SEC-AU-10). |
| `ATT` | App attestation (mobile) or proof-of-work (web/anon) required (SEC-MOB-3, SEC-BF-7). |
| `IDEM` | `Idempotency-Key` header required (SEC-IC-1). |
| `ETAG` | `If-Match` header required (SEC-IC-4). |
| `RL(bucket)` | Rate-limit bucket (§2.8). Every operation also has the default bucket of its tag. |
| `ENT(key)` | Plan entitlement checked server-side in the same transaction (Plan WP3). |
| `CNS(type)` | Consent of `consent_type` checked at read/write time (SEC-AZ-8). |
| `FLAG(key)` | Feature flag; when off the operation returns `403 FEATURE_DISABLED` (AI flags: `503 AI_UNAVAILABLE`). |
| `ASYNC` | Returns `202 Job`; result is fetched through `jobs.get`. |
| `AUD` | Writes an `AuditLog` entry. |
| `RSN` | Request body must contain `reason: Str<3,500>`. |
| `4EYES` | Takes effect only after a second, different staff member approves (SEC-ADM-6). |
| `PURP` | `CarPal-Access-Purpose` header required (SEC-ADM-5). |
| `PII` | Response contains personal data: `Cache-Control: no-store`, and for staff a read-audit record (SEC-LOG-4). |

Tag composition rules:
- `A | B` on an operation that exists under two prefixes (`{V}`, `{A}`, `{RQ}`, user/org scopes): `A` applies to the first prefix (`{me}`), `B` to the second (`{org}`, `{flt}`).
- `TAG(arg: condition)` applies the tag only when the condition holds, e.g. `ENT(max_vehicles: if activating)`, `ETAG(if exists) IDEM(if new)`.
- `ORG(group: qualifier)` narrows a group, e.g. `ORG(FC: fleet_driver only)` = role group `FC` may invite drivers only.
- `ORG(by target)` / `ORG(by approver_role)`: the organization is resolved from the target record, not the path; SEC-AZ-2 applies to it.

# 1. Transport

## 1.1 Hosts

| Host (pilot values are region config) | Purpose | Reached by |
|---|---|---|
| `api.carpal.app` | Consumer and business API | Mobile app directly; web clients through their BFF |
| `id.carpal.app` | OAuth 2.1 / OIDC authorization server and hosted sign-in UI | All clients |
| `admin-api.carpal.app` | Admin plane (`{adm}`) | Admin BFF only, from the private network (SEC-ADM-1) |
| `media.carpal-usercontent.app` | Signed upload and download of media; separate registrable domain, cookieless | All clients |
| `cdn.carpal.app` | UI dictionary, vector map tiles, static region config | All clients |

Web clients call the **same paths** on their own origin (`https://app.carpal.app/api/v1/...`, `https://business.carpal.app/api/v1/...`, `https://admin.carpal.app/api/v1/admin/...`). The BFF forwards 1:1, attaches the server-held token, strips cookies and browser-only headers, and never adds, renames or widens fields (SEC-WEB-1).

## 1.2 Protocol rules

| ID | Rule |
|---|---|
| TR-1 | HTTPS only, **TLS 1.3 only** (TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256, TLS_AES_128_GCM_SHA256), HTTP/2 or HTTP/3. Port 80 is closed on API hosts (no redirect). 0-RTT early data is disabled. |
| TR-2 | `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` on every response. |
| TR-3 | Major version in the path (`/v1`). Within a major: new endpoints, new optional response fields and new enum values may be added; nothing is removed, renamed or made stricter. Clients ignore unknown response fields and map unknown enum values to `unknown`. |
| TR-4 | Deprecation uses `Deprecation` and `Sunset` headers with at least 180 days' notice (mobile release cycles). |
| TR-5 | Request bodies are `application/json; charset=utf-8` only. Two exceptions: the OAuth endpoints `/oauth/*` on `id.carpal.app` use form encoding as RFC 6749 requires (§6.2), and the direct-to-storage upload `PUT` carries raw bytes (§17). XML, other form posts and multipart are rejected with `415`. |
| TR-6 | Methods: `GET` (safe, no body), `POST`, `PATCH` (JSON Merge Patch semantics on the declared writable fields only), `PUT` (full replace of the declared writable fields), `DELETE` (no body). `HEAD`/`OPTIONS` return `405` on API hosts (no CORS, SEC-WEB-2). `X-HTTP-Method-Override` and similar headers are rejected. |
| TR-7 | Personal or location data never appears in URLs (paths or query strings): search text, coordinates, emails, phones, VINs and tokens are sent in bodies. This keeps them out of access logs, proxies and referrers. Operations that need them use `POST`. |
| TR-8 | Every response carries `CarPal-Request-Id` and `CarPal-Contract: 1.1.0` (the contract version of this document's header; additive changes under TR-3 raise the minor version). |

## 1.3 Request headers

| Header | Required | Rule |
|---|---|---|
| `Authorization` | All except `/oauth/*`, `/.well-known/*`, `health.get` | Mobile: `DPoP <access_token>`. BFF: `Bearer <access_token>` over mutual TLS (token bound to the client certificate, RFC 8705). Any other scheme → `401`. |
| `DPoP` | Mobile, every request | DPoP proof JWT (RFC 9449), SEC-AU-6. |
| `CarPal-Client` | Always | `<client_id>/<semver> (<os> <os_version>)`, regex `^[a-z0-9-]{3,40}/\d+\.\d+\.\d+ \([a-z]+ [0-9.]{1,15}\)$`. Must equal the token's `client_id`. Below the minimum supported version → `400 CLIENT_UPGRADE_REQUIRED`. |
| `Content-Type` | With a body | `application/json; charset=utf-8` |
| `Accept-Language` | Optional | Enabled locale (`fa`, `en`). Anything else resolves to `en` (52 §2.4 read rule). |
| `Idempotency-Key` | `IDEM` operations | UUID (v4 or v7). SEC-IC-1. |
| `If-Match` | `ETAG` operations | `"v<version>"` from the last read. SEC-IC-4. |
| `CarPal-Request-Id` | Optional | UUID; echoed. Any other format is replaced by a server value (prevents log injection). |
| `CarPal-Attestation` | `ATT` operations, mobile | App Attest assertion (iOS) or Play Integrity token (Android). SEC-MOB-3. |
| `CarPal-PoW` | `ATT` operations when attestation is unavailable | `<challenge_id>.<nonce>` solving the proof-of-work challenge (SEC-BF-7). |
| `CarPal-Access-Purpose` | `PURP` operations (admin) | `case:<Id>` \| `dispute:<Id>` \| `dsr:<Id>` \| `verification:<Id>` \| `approval:<Id>`. The referenced item must be assigned to the caller or open in their queue. |
| `CarPal-Reason` | `RSN` operations answered by `DELETE` (admin) | The reason (3–500 characters, one line; percent-encoded when not ASCII), because a `DELETE` has no body (TR-6): `admin.platform_role_revoke`, `admin.synonym_delete`. Missing or invalid → `422 VALIDATION_FAILED` at `/reason`. |
| `CarPal-Timezone` | Optional | IANA name from the tzdb allowlist; used only for "open now" and slot display. |

## 1.4 Response headers

| Header | When | Rule |
|---|---|---|
| `CarPal-Request-Id`, `CarPal-Contract` | Always | TR-8 |
| `Content-Type` | With a body | `application/json` or `application/problem+json` |
| `Content-Language` | Localized content | Locale actually returned |
| `ETag` | Versioned resources | `"v<version>"` |

| `RateLimit-Policy`, `RateLimit`, `Retry-After` | Always / on `429`, `503` | IETF RateLimit header fields |
| `CarPal-Retry-After-Ms` | On `429`, `503` | Milliseconds the client must wait before retrying (SEC-RL-1) |

| `Idempotent-Replayed: true` | Replayed `IDEM` response | SEC-IC-2 |
| `WWW-Authenticate` | `401` | Includes `error`, and for step-up `acr_values` and `max_age` (RFC 9470) |
| Security headers | Always | `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; sandbox`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`, TR-2. No `Server`, `X-Powered-By` or framework version headers. |

## 2.3 Authentication — SEC-AU

| ID | Rule |
|---|---|
| SEC-AU-1 | OAuth 2.1 / OIDC. Only authorization code + PKCE S256 (plus client credentials for `cp-ssr` and the anonymous grant, SEC-AU-14). Implicit and password grants are disabled. `redirect_uri` is an exact string match against the registered list; mobile uses claimed HTTPS links (universal / app links), never custom URL schemes. `state` and `nonce` are required. |
| SEC-AU-2 | Access tokens are JWTs with `typ: at+jwt` (RFC 9068), signed **EdDSA (Ed25519)**. The `alg` allowlist is `EdDSA` only; `none`, HMAC and RSA are rejected. `kid` is required and must be in `https://id.carpal.app/.well-known/jwks.json`. Tokens with `jku`, `x5u`, `jwk` or unknown `crit` headers are rejected. `iss`, `aud` (the API host), `exp`, `nbf`, `iat` (skew ≤ 30 s), `client_id`, `sid`, `acr`, `auth_time` and `cnf` are validated on every request. |
| SEC-AU-3 | Tokens carry **no roles, organization IDs or permissions**. Authorization is resolved per request from server state (Redis cache ≤ 30 s, invalidated on any membership, role or status change), so a removed role stops working at once. |
| SEC-AU-4 | Every request checks `sid` against the session store; logout, password change, MFA change, account suspension and "sign out everywhere" revoke sessions within 1 s. |
| SEC-AU-5 | Refresh tokens are opaque, 256-bit, single-use and rotated on every use. Reuse of a rotated refresh token revokes the whole token family and notifies the user (`system_announcement`, critical). |
| SEC-AU-6 | DPoP (mobile): one proof per request; `htm` and `htu` (scheme, host, path; no query) must match; `iat` within ±60 s; `jti` unique per key for 5 min; `ath` = base64url(SHA-256(access token)). The server may require a nonce (`DPoP-Nonce`); a nonce is always required at `/oauth/token`. |
| SEC-AU-7 | Passwords: 12–128 characters, checked against a breached-password list, no composition rules, hashed with Argon2id (memory 64 MiB, iterations 3, parallelism 1, 16-byte salt) plus a KMS-held pepper. |
| SEC-AU-8 | One-time codes: 6 digits from a CSPRNG, valid 10 min, invalidated after 5 wrong attempts, resend after ≥ 60 s, ≤ 5 sends per destination per day. SMS goes only to country codes on the region allowlist (anti SMS-pumping). Codes are compared in constant time and stored as HMAC. |
| SEC-AU-9 | MFA: TOTP (RFC 6238, 30 s step, ±1 step, a used step cannot be reused) and WebAuthn passkeys (`userVerification: required`). Platform staff must use WebAuthn; TOTP is not accepted for staff. |
| SEC-AU-10 | Assurance levels: `aal1` = password, OTP or social login; `aal2` = aal1 + second factor, or a passkey; `aal3` = hardware-bound WebAuthn (staff). Step-up uses the RFC 9470 challenge: `401 STEP_UP_REQUIRED` with `WWW-Authenticate: DPoP error="insufficient_user_authentication", acr_values="aal2", max_age=600`. |
| SEC-AU-11 | Enumeration resistance: sign-up, sign-in, OTP and password-reset start operations return the same status, body shape and a fixed minimum latency (400 ms + random 0–50 ms) whether or not the account exists. Sign-up with an existing email sends a notice to that address instead of revealing it. Sign-in failures always return `INVALID_CREDENTIALS`. |
| SEC-AU-12 | Risk-based sign-in: a new device or an unusual network sends a security notification; impossible travel or a high risk score forces step-up. Failed sign-ins slow down exponentially per account and per IP prefix; there is no hard lockout that an attacker could trigger against a victim. |
| SEC-AU-13 | Social login (Google, Apple): `iss`, `aud`, `nonce` and `email_verified` are validated. Linking a social identity to an existing account needs the user to sign in to that account first (prevents pre-account hijacking). |
| SEC-AU-14 | Anonymous access: `cp-mobile` gets an anonymous token through `grant_type=urn:carpal:params:oauth:grant-type:anonymous` with `ATT`. It is DPoP-bound, lasts 15 min, has no refresh, and carries scope `public.read search`. Consumer web visitors get the same through the BFF session. Every `PUB` call is therefore attributable to a device key for rate limiting. |

## 2.4 Authorization — SEC-AZ

| ID | Rule |
|---|---|
| SEC-AZ-1 | **Fail closed.** Every route declares its `sec:` tags in code from this contract. A route without a declaration is not registered (`404`). Admin routes are registered only on the admin host. |
| SEC-AZ-2 | **Tenant from path.** For `{org}`, `{prv}`, `{vnd}`, `{flt}` the caller must hold an active `RoleMembership` in `org_id` with an allowed role, and the organization type must match the alias. Otherwise `404 NOT_FOUND`, never `403`, so the existence of private records is not disclosed. |
| SEC-AZ-3 | **Object scoping.** Every lookup includes the owner predicate (`owner_user_id` or `organization_id`) and runs in a transaction that sets the PostgreSQL RLS context (`app.user_id`, `app.org_id`, `app.role`). RLS is the second wall: a code defect still cannot cross tenants. An object outside the caller's scope is `404 NOT_FOUND`. |
| SEC-AZ-4 | **References in bodies.** Every `Id` in a request body (vehicle, media, location, node, appointment …) is checked against the caller's rights. An ID the caller may not read is reported exactly like a non-existent ID: `422 REFERENCE_NOT_FOUND` with its JSON pointer. |
| SEC-AZ-5 | **Property level.** Each operation has its own input type; only the fields in it can be written. System fields and fields of other audiences are rejected (`422 READ_ONLY_FIELD` / `UNKNOWN_FIELD`). Responses use audience projections: `Public*` (anyone), plain name (owner or member), `Staff*` (admin plane). A projection is built by allowlist, never by removing fields from the entity. |
| SEC-AZ-6 | **Function level.** Role sets per operation (§0.5). Staff roles never work on the consumer/business host, and consumer tokens never work on the admin host (different `aud`). |
| SEC-AZ-7 | **Fleet drivers** (`DRV`) can read and report only on vehicles with an active assignment to them, checked per request. Fleet records reached without a vehicle in the path follow the same rule: a driver sees the fleet's media only when they uploaded it or it is attached to a record of an assigned vehicle (changes: own uploads only), never the fleet's AI insights and suggestions (requested by `FC`/`F+`), and every `{flt}` vehicle and appointment read carries `DRV`. |
| SEC-AZ-8 | **Consent gates** are evaluated on every read of shared data (vehicle context for providers, service history in the pre-visit report, fitment context for vendors, driver data for fleet managers, location for search). Consent-gated data is never cached; withdrawal takes effect on the next request. |
| SEC-AZ-9 | **Entitlements** (vehicle limits, inventory limits, imports, exports, AI tools) are checked server-side inside the write transaction with a row lock on the counter, so parallel requests cannot exceed a limit. |
| SEC-AZ-10 | **Separation of duties.** Members of an organization cannot review it, invite reviews to themselves, confirm their own Path 2 review, or react "helpful" to its reviews. Staff cannot decide an item they raised, and an appeal or `review_approval_objection` is decided by a different staff member from the first decision (52 §11). |

## 2.5 Input hardening — SEC-IN

| ID | Rule |
|---|---|
| SEC-IN-1 | Limits: body ≤ 64 KiB unless the operation says otherwise; JSON depth ≤ 8; ≤ 1,000 total keys; arrays ≤ their declared maximum; strings ≤ their declared maximum (in Unicode code points). Exceeding a limit is `413 PAYLOAD_TOO_LARGE` or `422 VALIDATION_FAILED`. |
| SEC-IN-2 | Parsing: strict UTF-8; duplicate object keys rejected; keys `__proto__`, `constructor`, `prototype` rejected at any depth; numbers in exponent form rejected; integers outside the declared range rejected; decimals and money are strings (§3). |
| SEC-IN-3 | Closed schemas: unknown body fields → `422 UNKNOWN_FIELD`; unknown or repeated query parameters → `400 UNKNOWN_QUERY_PARAM`; `null` only where declared. |
| SEC-IN-4 | Text normalization (52 §2.5, §22): trim; Unicode NFC; Persian/Arabic-Indic digits → Latin in numeric and code fields; Arabic `ي`/`ك` → Persian in normalized and search fields. Rejected characters: C0/C1 controls (except `\n` and `\t` in `Text`), unpaired surrogates, noncharacters, and bidirectional embedding/override/isolate controls (U+202A–U+202E, U+2066–U+2069). ZWNJ, ZWJ, LRM and RLM are allowed (Persian). |
| SEC-IN-5 | All text is plain text. The API never returns HTML; clients render text as text, never as HTML or Markdown. Display names and organization names go through a confusable check (Unicode UTS #39 skeleton) against verified organizations; a near match opens an `impersonation` moderation case. |
| SEC-IN-6 | Enumerated inputs only for sorting, filtering and grouping. There is no free-form filter syntax, and no search-engine query language is passed through: query text is sent to Elasticsearch as a parameter of a fixed `match`-family query, never through `query_string`. All SQL is parameterized. |
| SEC-IN-7 | Regular expressions used on client data run on a linear-time engine (RE2), so crafted input cannot cause catastrophic backtracking. |
| SEC-IN-8 | Path parameters are validated (`Id`, `Slug`) before routing. Path traversal sequences and encoded slashes are rejected at the edge. Ambiguous framing (`Content-Length` with `Transfer-Encoding`) is rejected at the edge. |
| SEC-IN-9 | **No general server-side fetch of client URLs.** `Organization.website` is stored and displayed, never fetched. Uploads go to pre-signed storage URLs generated by the server. The single controlled exception is `geo.resolve_map_link`: a full map URL is parsed locally (coordinate patterns per provider, no network call); a short link is expanded only if its host is in the region's `map_link_hosts` allowlist, through the egress proxy that blocks private, loopback, link-local and metadata address ranges, with DNS resolved once and pinned, no cookies or credentials, at most 3 redirects each re-checked against the allowlist, only the `Location` header read (no body), a 3 s timeout, and the final URL parsed locally like a full URL. |
| SEC-IN-10 | Data from third parties (VIN decoder, geocoder, LLM output, email/push provider callbacks) is validated against the same schemas as client input before use. Provider callbacks arrive on a separate internal ingress with signature verification and are not part of this contract. |
| SEC-IN-11 | CSV imports are parsed as data with a strict dialect (UTF-8, RFC 4180), ≤ 20 MB, ≤ 20,000 rows, ≤ 64 columns, cells ≤ 2,000 characters. CSV exports neutralize formula injection: a cell that starts with `=`, `+`, `-`, `@`, tab or carriage return is prefixed with `'`. |

| ID | Rule |
|---|---|
| SEC-OUT-1 | Never returned by any operation: password hashes, credential references, token hashes, link tokens after issue, storage keys, KMS references, internal scoring weights (`trust_weight`), internal AI flags (`ai_sentiment`, `ai_complaint_flags`), `price_trade` to anyone other than the vendor's own members or members of an organization with an approved trade account, `Embedding` vectors. |

## 2.7 Idempotency and concurrency — SEC-IC

| ID | Rule |
|---|---|
| SEC-IC-1 | `IDEM` operations require `Idempotency-Key`. Missing → `428 IDEMPOTENCY_KEY_REQUIRED`. Keys are stored 24 h per (principal, operation, key) with a SHA-256 hash of the request body. |
| SEC-IC-2 | Same key and same body → the original status and body are replayed with `Idempotent-Replayed: true`. Same key, different body → `422 IDEMPOTENCY_KEY_REUSED`. Same key still running → `409 IDEMPOTENCY_IN_PROGRESS`. |
| SEC-IC-3 | All responses of versioned resources carry `ETag: "v<version>"`; the `version` field is also in the body. |
| SEC-IC-4 | `ETAG` operations require `If-Match`. Missing → `428 PRECONDITION_REQUIRED`; stale → `412 VERSION_MISMATCH` (no lost updates). |
| SEC-IC-5 | State transitions (appointments, reviews, inquiries, approvals, disputes) lock the row and re-validate the transition inside the transaction. **Server-directed retry delay (backpressure).** The backend can tell any client (mobile app, consumer web, portals, admin console) how many milliseconds to wait before calling again, so retries and polling cannot clog the servers.

| ID | Rule |
|---|---|
| SEC-RL-1 | On `429` and `503` the server sends `CarPal-Retry-After-Ms: <Int<100,3600000>>`, the same value in the body as `retry_after_ms`, and the standard `Retry-After` in whole seconds (rounded up) for intermediaries. |
| SEC-RL-2 | **Load shedding.** When a service is overloaded, the gateway may refuse requests early with `503 OVERLOADED` and a retry delay, by priority: analytics events and AI requests are shed first, then search and map, then other reads, then writes. Sign-in, token refresh, appointment transitions and admin kill-switch operations are shed last. |
| SEC-RL-3 | **Polling pace.** Responses of pollable operations (`jobs.get`, `notifications.unread_count`, `inventory.import_get`, `admin.four_eyes_list`, the lists clients refresh on a timer) may carry `CarPal-Poll-After-Ms: <Int<1000,3600000>>`; the client does not call that operation again before the delay ends. The server raises the value under load. |
| SEC-RL-4 | **Client obligations** (all clients; enforced by contract tests): never retry or poll before the given delay; add random jitter of 0–20 % on top; when no delay is given, retry with exponential backoff and full jitter (base 500 ms, cap 30 s, at most 5 attempts). Only safe methods and `IDEM` requests (same `Idempotency-Key`) are retried automatically; other writes are retried only by the user. After 3 consecutive `503`s for an operation, the client pauses that operation for the last given delay and shows a "try again shortly" state instead of looping. |
| SEC-RL-5 | BFFs pass `CarPal-Retry-After-Ms`, `CarPal-Poll-After-Ms` and `retry_after_ms` to the browser unchanged, and apply the same rules to their own calls to the API. |
| SEC-RL-6 | The delay is computed by the server per token key, user, organization, operation and current load; it is a hint for well-behaved clients, while the limits in the table above are still enforced for clients that ignore it. |

## 3.3 Pagination

List operations take `q: cursor?: Cursor, limit?: Int<1,50>=20` (admin: `Int<1,100>`) and return `Page<T>`. Sort and filter parameters are enumerated per operation; the cursor carries them, so a cursor cannot be combined with different filters (`400 CURSOR_MISMATCH`). In operation blocks, `cursor?, limit?` is shorthand for these two parameters, and list operations that show no `q:` line accept only them.

## 6.2 Authorization server (`id.carpal.app`)

The `/oauth/*` endpoints use the OAuth form encoding (`application/x-www-form-urlencoded`, RFC 6749); this is the only exception to TR-5 besides the storage `PUT`. The `/v1/auth/*` endpoints are used only by the hosted sign-in UI on `id.carpal.app`; they are bound to an `interaction_id` (created by `auth.authorize`, held in a `__Host-cp_ia` cookie) and protected by SEC-WEB-3.

Standard types used here: `OidcDiscovery` (OpenID Connect Discovery 1.0), `Jwks` (RFC 7517; `kty: OKP`, `crv: Ed25519` only), `TokenRequest` (RFC 6749 §4.1.3 and §6, RFC 7523 `private_key_jwt`, RFC 9449 DPoP), `WebAuthnOptions` / `WebAuthnAssertion` / `WebAuthnAttestation` (WebAuthn Level 3 JSON serializations of `PublicKeyCredentialRequestOptions` / `CreationOptions` and the resulting credentials; `attestation: none`, `userVerification: required`).

#### auth.discovery
Returns the OIDC discovery document so clients learn endpoints, supported algorithms (`EdDSA` for tokens, `ES256` for DPoP) and the PKCE method `S256`. Cacheable for 1 h.
```
GET /.well-known/openid-configuration -> 200 OidcDiscovery
in:   -
sec:  PUB(no token)
```

#### auth.jwks
Returns the public signing keys for access and ID tokens; during rotation two keys are listed (SEC-CR). Cacheable for 10 min.
```
GET /.well-known/jwks.json -> 200 Jwks
in:   -
sec:  PUB(no token)
```

#### auth.authorize
Starts an authorization-code flow with PKCE and redirects the system browser to the hosted sign-in UI; only registered exact `redirect_uri` values are accepted, and errors never redirect to an unregistered URI (no open redirect).
```
GET /oauth/authorize -> 302 (hosted sign-in)
q:    response_type: 'code', client_id: Str, redirect_uri: Url, scope: Str<1,200>, state: Str<22,128>,
      nonce: Str<22,128>, code_challenge: Str<43,128>, code_challenge_method: 'S256',
      acr_values?: 'aal1'|'aal2'|'aal3', ui_locales?: Locale, prompt?: 'login'|'none'
sec:  PUB(no token) RL(auth.signin)
```

#### auth.token
Exchanges an authorization code (with `code_verifier`), a refresh token (rotation, SEC-AU-5), client credentials (`cp-ssr`) or the anonymous grant (SEC-AU-14) for tokens; mobile requests carry a DPoP proof with a server nonce, BFFs authenticate with `private_key_jwt` over mTLS.
```
POST /oauth/token -> 200 TokenResponse
in:   TokenRequest (form)  // grant_type: authorization_code | refresh_token | client_credentials | urn:carpal:params:oauth:grant-type:anonymous
sec:  PUB(no token) ATT(anonymous grant, cp-mobile code grant) RL(auth.signin)
err:  400 invalid_grant, 400 invalid_dpop_proof, 400 use_dpop_nonce, 401 invalid_client
```
```ts
type TokenResponse = { access_token: string; token_type: 'DPoP'|'Bearer'; expires_in: Int<60,900>;
  refresh_token?: string; id_token?: string; scope: string }
```

#### auth.revoke
Revokes a refresh token (and its family) or an access token's session; always returns 200 so token validity cannot be probed.
```
POST /oauth/revoke -> 200 (empty)
in:   token, token_type_hint? (form)
sec:  PUB(no token) RL(default.write)
```

#### auth.pow_challenge
Issues a proof-of-work challenge for clients that cannot attest (SEC-BF-7); the difficulty grows with the risk score of the IP prefix and device.
```
POST /oauth/challenge -> 200 PowChallenge
in:   { purpose: 'anonymous'|'signup'|'signin'|'review'|'invitation' }
sec:  PUB(no token) RL(public.read)
```
```ts
type PowChallenge = { challenge_id: Id; prefix: Str<16,64>; difficulty_bits: Int<8,32>; expires_at: DateTime }
```

#### auth.signup
Creates an account inside the current sign-in interaction (email + password, or email/phone for OTP-only sign-up) and sends a verification; the response is identical whether or not the email already exists (SEC-AU-11).
```
POST /v1/auth/signup -> 202 AuthNext
in:   { interaction_id: Id; full_name: Str<2,100>; email: Email; password?: Str<12,128>; phone?: Phone;
        locale: Locale; terms_version: Str<1,20>; privacy_policy_version: Str<1,20> }
sec:  PUB(no token) ATT IDEM RL(auth.signin)
emit: user.registered (after email verification)
```

#### auth.signin_password
Verifies email and password inside the interaction and returns the next step (MFA or complete); every failure is `INVALID_CREDENTIALS` with a fixed minimum latency.
```
POST /v1/auth/signin -> 200 AuthNext
in:   { interaction_id: Id; email: Email; password: Str<1,128> }
sec:  PUB(no token) ATT RL(auth.signin)
err:  401 INVALID_CREDENTIALS
```

#### auth.otp_start
Sends a one-time sign-in or verification code to an email or a phone number on the region allowlist; always `202` with the same body.
```
POST /v1/auth/otp/start -> 202 Ack
in:   { interaction_id: Id; channel: 'email'|'sms'; destination: Email | Phone; purpose: 'signin'|'verify' }
sec:  PUB(no token) ATT RL(auth.otp)
```

## 14.2 Search and map operations

#### search.run
Runs one search (direct search, map list, Help Me follow-up or fleet search): normalizes the text, interprets it into editable chips, runs the server-side safety check, ranks results with stored structured reasons and returns the first page. With `facets: true` it also counts the results per filter option and per removed filter (`SearchFacets`) from the same retrieval and stores the counts with the session. Plan, payment or sponsorship never affects ranking.
```
POST /v1/search -> 200 SearchResponse
in:   SearchRequest
sec:  PUB RL(search)
err:  403 LOCATION_CONSENT_REQUIRED, 401 UNAUTHENTICATED(vehicle_id or user_position without sign-in)
emit: search.started, search.zero_result (analytics)
```

#### search.page
Returns a page of a search session owned by the caller: the page after the cursor's position.
```
GET /v1/search/{session_id}/results -> 200 Page<ResultCard>
q:    cursor: Cursor, limit?: Int<1,50>=20
sec:  PUB RL(search)
```

#### search.session_get
Returns a search session owned by the caller again from its first page (page reload, Back after the browser discarded the tab, a new tab of the same caller): the stored interpretation, safety block, vehicle-filter fallback and facets, and result cards rendered from the stored ranks with current public data, as `search.page` does. The ranking does not run again and no analytics event is emitted. A session can be read for 24 hours after it was created; `next_cursor` is a new cursor.
```
GET /v1/search/{session_id} -> 200 SearchResponse
q:    limit?: Int<1,50>=20
sec:  PUB RL(search)
err:  404 NOT_FOUND(another caller's session, or older than 24 hours)
```

#### search.refine
Re-runs a session with edited chips, filters, location, vehicle filter or sort and returns a new session; the ranking rules are unchanged. `facets` defaults to the value of the refined session.
```
POST /v1/search/{session_id}/refine -> 200 SearchResponse
in:   { intent_override?: InterpretedIntent; filters?: SearchFilters; location?: LocationInput;
        vehicle_filter_applied?: boolean; sort?: SearchSort; facets?: boolean }
sec:  PUB RL(search)
emit: search.chip_edited (analytics, when chips changed)
```

#### search.result_event
Records that a result was viewed or selected (match acceptance metric).
```
POST /v1/search/{session_id}/results/{result_id}/events -> 200 Ack
in:   { event: 'viewed'|'selected' }
sec:  PUB RL(default.write)
```

#### map.pins
Returns one pin per business location in the viewport (public fields only, public points, clusters by zoom), with highlight and vehicle-relevance flags; never any featured or paid pin. Every `SearchFilters` member that applies to businesses sets `matches_filters`; `open_now` is judged per location (that location's hours) and `available_within_days` per organization (its next open slot). With `only_matching` the pins that miss the filters are left out before clustering. With `search_session_id` (a session of the caller) pins carry the session's rank, first reason and `result_id`.
```
POST /v1/map/pins -> 200 MapResponse
in:   MapQuery
sec:  PUB RL(map) FLAG(map.enabled)
err:  422 VALIDATION_FAILED(bbox_too_large)
emit: map.opened (analytics, first call of a map session)
```

#### safety.check
Runs the shared safety keyword check on free text (request descriptions, issue text) so clients can show the safety banner before sending; the same check runs again on submission.
```
POST /v1/safety/check -> 200 SafetyBlock
in:   { text: Text<3000>; locale?: Locale }
sec:  PUB RL(search)
```

# Appendix C. Contract Test Obligations (WP21)

Generated from this document and run in CI against every build:

1. **Schema conformance:** every operation's request and response validates against the closed schemas; unknown fields, unknown query parameters, `S` fields in input and out-of-range values are rejected with the documented codes.
2. **BOLA matrix:** for every operation with a path ID or body reference, a caller from another user or organization gets `404 NOT_FOUND` / `422 REFERENCE_NOT_FOUND` and never data.
3. **BFLA matrix:** for every operation, every role outside its `sec:` set is refused; admin operations are unreachable on `api` and consumer tokens are refused on `admin-api`.
4. **Projection tests:** no response contains a field from SEC-OUT-1; approximate locations return only the public point and no street address before confirmation; trade prices appear only with an approved trade account.
5. **Security mechanics:** DPoP replay and wrong `htu` rejected; refresh-token reuse revokes the family; `IDEM` replay and conflict behaviour; `ETAG` lost-update protection; single-use link tokens under concurrency; step-up challenges; enumeration-resistant timings within tolerance; `geo.resolve_map_link` refuses non-allowlisted hosts, private addresses and off-list redirects.
6. **Rate limits and backpressure:** each bucket in §2.8 returns `429` with `CarPal-Retry-After-Ms` at its threshold; forced load shedding returns `503 OVERLOADED` with a delay; client test suites (mobile, web, admin) verify that no request is repeated before the delay, that only safe and `IDEM` requests retry automatically, and that `CarPal-Poll-After-Ms` slows polling.
7. **Business rules:** review path selection (appointment states, late-closed appointments, 7-day window), Path 2 approval states, appointment and inquiry transition tables, vehicle and inventory limits under parallel requests, kill switch → `503 AI_UNAVAILABLE` while search, profiles and appointments still succeed.
