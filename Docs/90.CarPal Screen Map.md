# 1. Screen Mapping Principles

For the MVP, the product should feel:

- **Trust-first**
- **Vehicle-context aware**
- **AI-assisted but human-controlled**
- **Simple for users, powerful for businesses**
- **Consistent across roles**

The MVP should avoid overloading users with unnecessary screens. Each screen should have a clear job.

## Core screen rules

1. **Every major search or recommendation should preserve vehicle context.**
   - If the user selects a BMW 3 Series, search and matching should adapt automatically.

2. **Every provider or vendor profile should make trust visible.**
   - Ratings, badges, evidence, portfolio, reviews, response behavior.

3. **AI should appear as assistance, not as uncontrolled automation.**
   - Drafts, suggestions, explanations, summaries.

4. **Every role should have a clear home dashboard.**
   - Consumer: Discover/Garage
   - Provider: Requests and reputation
   - Vendor: Inventory and inquiries
   - Fleet: Vehicle health and approvals
   - Admin: moderation and trust operations

5. **Critical states must be designed from the start.**
   - Empty
   - Loading
   - Error
   - No permission
   - Pending verification
   - Limit reached
   - No results
   - Safety warning

6. **Search never needs Help Me.**
   - Every provider, vendor and part can be found with plain search in the user's own language (Persian and English, mixed script, Persian typed in Latin letters) and on the map. Help Me is offered, never forced.
   - Safety words in search text or request notes always show the safety banner, and the results stay visible.

7. **Reviews are confirmed in one of two ways.**
   - **Verified visit:** written after a confirmed appointment; verified automatically, the shop does not approve it.
   - **Approved by the business and CarPal:** written without an appointment; the business confirms the customer relationship and a CarPal reviewer approves it. It counts for less.
   - There is no separate "unverified" section.

# 2. Screen ID Convention

To make the MVP easier to manage, each screen gets an ID.

| Prefix | Area |
|---|---|
| S | Shared screens |
| C | Consumer / individual user |
| P | Service provider portal |
| V | Vendor portal |
| F | Fleet / corporate portal |
| A | Admin console |
| W | Consumer web (PWA) screens that mirror a mobile screen (defined in Doc 22) |

Example:

- `C-HELP-02` = Consumer Help Me AI triage screen
- `P-REV-02` = Provider review detail and response screen
- `V-INV-03` = Vendor inventory item edit screen
- `F-APP-02` = Fleet appointment approval screen
- `A-AI-01` = Admin AI oversight dashboard

## S-SHARED-01 — Global Search Entry

### Purpose

Provide a consistent search entry point that works without Help Me.

### Key elements

- Search input: accepts text in any supported language, mixed scripts, and Persian typed in Latin letters. The text is normalized (letter forms, digits, spacing) before matching.
- **Browse on map** button beside the field (opens `S-SHARED-02` with the same vehicle and location)
- Recent searches
- Suggested categories
- Vehicle context chip
- Location context chip
- Search modes:
  - **All** (default; shops and parts sellers together)
  - Providers
  - Vendors
  - Parts
  - Showcases
  - Q&A
- Live suggestions grouped as Services, Symptoms (a symptom shows the shops for the mapped system), Shops and Parts

### Behavior

- Under any search box the app shows how it understood the text (for example "Wheels & tyres · Toyota Corolla") as **editable chips**.
- Safety words (brakes, steering, smoke, overheating, airbag, loss of power) show a red safety banner with **Find urgent help** above the results. The results stay visible.
- Help Me appears only as a quiet suggestion under symptom-style results.

### AI behavior

- Interpretation is **rule-based first** (taxonomy, synonyms, transliteration) and works with AI off. AI is an optional enhancer.
- Suggest likely categories from partial text
- Detect vehicle-related and symptom-related intent

---

## S-SHARED-02 — Map View

### Purpose

Choose shops and parts sellers by location, with the same results, filters and explanations as the lists.

### Entry points

- **Browse on map** (Home, Search Entry)
- The list/map toggle on search results and parts results
- **See more shops** in Help Me recommendations (the 3 recommended shops carry the numbers 1–3; urgent providers come first for safety-critical issues)
- The Location tab of a provider or vendor profile (centred on that business)
- Fleet provider selection

It is not a tab.

### Key elements

- Top bar with compact search, query chips and a list toggle
- Filter row: the **"For [car]" vehicle filter** (on by default when a vehicle is selected), layer chips **Shops** and **Parts sellers**, **Open now**, **Advanced search**
- Map canvas: OpenStreetMap data served from CarPal's own servers, "© OpenStreetMap contributors" always visible, labels in the app language
- Pins: one per business location; shops and parts sellers use different shapes and icons (never colour alone); a parts seller's pin groups its matching parts ("3 parts fit your car"); hybrids show both; mobile providers show their service radius circle; clusters show counts (at most 200 pins per view)
- Selected-pin card: name, about how far, rating, badge, one-line match reason, open-now status; buttons **Request appointment** (primary) or **Ask about part**, **Directions** (secondary), **View**
- **Search this area** (the distance factor then runs from the map centre; ranking rules are unchanged)
- Recenter button, zoom buttons, legend

### Rules

- Vehicle filter: if fewer than 3 pins remain, the map says so and offers **Show all nearby**.
- Advanced search highlights matching pins and dims the rest (still tappable), with a **Hide others** switch.
- Public data only: no trade prices, no private data. **No featured or paid pins.**
- Distances are straight-line and labelled "about". The user's position is used only with location consent.
- Every pin is also reachable as a list item; controls mirror in RTL while the map does not.

### States

- Location permission denied (map opens on a chosen city)
- No vehicle selected (the vehicle filter is hidden)
- No results in area
- Loading
- Error loading map (falls back to the list)
- Offline (saved list; last viewed area if cached)

## 5.7 Review Screens

---

## C-REV-01 — Write Review (visit-based and approval-based)

### Purpose

Capture a structured, trustworthy review in under two minutes.

### Entry points

- Review invitation notification, or the **email link** (a personal link that works once and expires 7 days after it is sent; `S-AUTH-07` asks for a one-time code first)
- Completed appointment
- Service record
- **Write a review** on a provider profile

### Two ways a review is confirmed

| | Visit-based | Approval-based |
|---|---|---|
| When | The user had an appointment that was confirmed and took place, and writes within 7 days of the invitation | No appointment, or the 7-day window has passed (the appointment is then attached as evidence) |
| What happens | Verified automatically after the safety and abuse checks. The shop does not approve it and cannot block it. | Hidden, “Waiting for approval”. The business has 7 days to confirm the user was its customer (silence means no objection), then a CarPal reviewer approves. |
| Label | **Verified visit** | **Approved by the business and CarPal** |
| Weight in the score | Full | Lower |

If the business rejects an approval, the review goes to dispute handling; the user can add evidence and a CarPal reviewer decides.

### Fields

- Overall stars
- Sub-ratings
- Review text
- Service category
- Tags
- Photo upload optional
- Context header: “Verified visit · BMW 3 Series · Suspension” or “No appointment — the shop and CarPal will check this review before it is published”
- Consent to display vehicle model/category
- Submit (approval-based: **Send for approval**)

### AI behavior

- Suggest tags
- Warn about private information
- Encourage specific details
- Detect potentially unsafe or abusive content (risk checks only; AI never approves or rejects)

### States

- No confirmed appointment (approval-based mode)
- Window passed (approval-based mode, appointment attached)
- Link expired or already used (clear message, with **Write a review from the profile**)
- Duplicate review warning
- Moderation notice
- Success confirmation

---

## C-REV-02 — Review Submitted

### Purpose

Confirm review submission.

### Content

- Thank you message
- Review status: visit-based “Being checked — usually published within minutes”; approval-based “Waiting for approval — the shop has up to 7 days to confirm you were its customer, then CarPal checks it”
- Moderation notice if needed
- Link back to provider
- Link to service history

## P-REV-04 — Review Approval Request (new)

### Purpose

Confirm whether the business recognises the author of a review that was written without an appointment (the approval-based path).

### Elements

- Card in the Review Inbox and on the Dashboard: **Approval needed — do you recognise this customer?**
- The author's display name, the date and the kind of work. Nothing else is shown, and the review cannot be edited or answered at this step.
- Actions: **Yes, this was our customer**, **I don't recognise this customer**, **Not sure** (ask CarPal)
- Deadline: 7 days; reminders proposed at day 3 and day 6

### Rules

- The question is about the relationship, not the opinion. A rating alone is never a reason to reject.
- No answer in 7 days means no objection, and a CarPal reviewer decides.
- A rejection does not remove or publish the review automatically: it opens a dispute where the author can add evidence and a CarPal reviewer decides. If upheld, the review shows “Disputed by the business”.
- A review written after a confirmed appointment never reaches this screen; the shop does not approve it.

### States

- Already answered
- Deadline passed
- Business sent the invitation itself (counts as already confirmed; no request is shown)

## A-REV-01 — Review Moderation and Approval Queue

- Reported
- AI flagged
- Suspicious pattern
- Disputed (including `review_approval_objection`, where the business rejected an approval)
- Pending automatic check failed

Reviews written after a confirmed appointment (the visit-based path) never enter the approval tab.

### Review detail elements

- Review text
- Rating
- Context and confirmation path
- Business answer (pending, confirmed, rejected, no response) and its date
- Author history and any evidence the author attached
- Appointment link
- Provider response
- AI risk score

### Actions

- Confirm (approval queue): the review becomes “Approved by the business and CarPal”
- Reject (approval queue): reason code required; the author can appeal
- Ask for evidence
- Approve
- Remove (audit reason required)
- Reduce weight
- Request more info
- Escalate

A low rating alone is never a reason to reject or remove.

# 11. Screen State Matrix

Every major screen should handle common states.

| State | Meaning | Example Handling |
|---|---|---|
| Loading | Data is fetching | Skeleton loaders |
| Empty | No records yet | CTA to add vehicle/provider/item |
| Error | Failure | Retry message |
| No permission | User cannot access | Explanation + request access |
| Pending verification | Trust not yet confirmed | Banner |
| Limit reached | Plan cap exceeded | Upgrade/remove prompt |
| No results | Search found nothing | Broaden filters/suggestions |
| Safety warning | Risky automotive issue | Urgent notice |
| Moderation pending | Content not public | Status label |
| Waiting for approval | A review without an appointment is hidden until the business and a CarPal reviewer approve it | “Waiting for approval” with who is being waited for |
| Link expired or used | A review invitation link is single use and expires 7 days after sending | Clear message and **Write a review from the profile** |
| AI unavailable | AI layer down | Manual fallback |

# 15. Final MVP Screen Map Summary

The MVP screen map can be summarized as:

## Consumer

A mobile-first experience where users manage vehicles, get AI-assisted help or simply search in their own language and on the map, find trusted providers/vendors, request appointments, open directions in their map app, and leave reviews that are confirmed by a visit or by the business and CarPal.

## Provider

A reputation and workflow portal where providers manage their capability portfolio, appointments, reviews, portfolio evidence, and AI-driven improvement insights.

## Vendor

A secure inventory management portal where vendors normalize, enrich, and expose searchable parts with fitment context.

## Fleet

A practical fleet maintenance portal where corporate users manage vehicles, drivers, issue reports, approvals, appointments, and cost reports.

## Admin

A trust operations console managing users, organizations, taxonomy, moderation, AI oversight, MCP audit, plans, and feature flags.
