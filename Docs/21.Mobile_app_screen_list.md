# CarPal MVP — Mobile App Screen List (Car Owner)

**App:** CarPal consumer app, React Native, iOS and Android (Plan WP19).
**User:** individual car owner on the Individual Free plan (MVP §3.1). Persona and journey: [10.User Story - Car Owner](10.User%20Story%20-%20Car%20Owner.md) (Sara).
**Builds on:** [90.CarPal Screen Map](90.CarPal%20Screen%20Map.md) (screen IDs and base elements), [55.UI-UX Critical Flow](55.UI-UX%20Critical%20Flow.md) (Help Me wizard IDs `C-HELP-01` to `C-HELP-08`), [56.UI-UX Social Flow](56.UI-UX%20Social%20Flow.md) (feed and composer), [52.MVP Data Dictionary](52.MVP%20Data%20Dictionary.md) (entity, status and consent names).
**Web version:** [22.Social_WebUI_user_screens](22.Social_WebUI_user_screens.md). **Admin side:** [23.Admin_WebUI_screens](23.Admin_WebUI_screens.md).

**How to read each screen:**
- **Purpose** and **Entry points**: why the screen exists and how the user gets there.
- **Layout and elements**: what is on the screen, top to bottom, and what each element does.
- **Interactions**: what the user does and how the app responds.
- **States**: loading, empty, error and special cases the screen must handle.
- **UX notes**: decisions that make the screen fast and easy to use.
- **Story**: the chapter of Story 10 where the screen is used.

Screen IDs marked **(new)** are not in Doc 90 or Doc 55. They are added here and listed in §8 for WP0 approval.

## 1. Experience principles

These rules apply to every screen in this document.

| # | Principle | What it means on screen |
| :--- | :--- | :--- |
| 1 | **Vehicle first** | The active vehicle is always visible as a chip on screens where it changes results (Discover, Search, Help Me, Parts). One tap changes it. |
| 2 | **Three taps to value** | From Home: start Help Me in 1 tap, open a recommended provider in 1 tap, request an appointment from a profile in 1 tap. Returning users rebook a favourite in 3 taps or fewer. |
| 3 | **Trust is visible, never implied** | Verified marks, evidence counts and match reasons are shown as text, not just icons. Unverified content is labelled. |
| 4 | **AI is labelled and optional** | Every AI output carries an "AI suggestion" label and an info icon that says what it is based on. The user accepts, edits or dismisses. Nothing AI-made is saved or published without a user action. |
| 5 | **Safety interrupts** | Safety warnings use a full-width red banner with an icon and plain text. They are never hidden behind a tap and never use colour alone. |
| 6 | **Never lose work** | Help Me, review, post, service record and question drafts autosave on every step. Leaving and coming back resumes the draft. |
| 7 | **Privacy at the moment of sharing** | Consent is asked where data leaves the user (appointment request, showcase, post), with a one-line explanation, not only at signup. |
| 8 | **Persian first, English equal** | RTL layout, Persian digits, Jalali dates for FA. Directional icons mirror; logos and media controls do not (Plan §3.2). User-typed text stays in the language it was written in. |
| 9 | **Reachable** | Primary actions sit in the bottom third of the screen (sticky bottom bar or floating button). Tap targets are at least 48 dp. Dynamic type up to 200% does not break layouts. |
| 10 | **Honest empty states** | Empty screens explain why and offer one clear next step. |
| 11 | **Search never needs Help Me** | Every provider, vendor, and part can be found with plain search in the user's own language, and on the map. Help Me is offered, never forced. Safety words in search always show the safety banner. |

## 2. App shell and navigation

### 2.1 Bottom tab bar

| Position (LTR order; mirrored in RTL) | Tab | Icon badge | Opens |
| :--- | :--- | :--- | :--- |
| 1 | **Discover** | none | `C-HOME-01` |
| 2 | **My Garage** | dot if a vehicle has an overdue reminder or an open safety issue | `C-GARAGE-01` (or `C-GARAGE-02` directly if the user has one vehicle) |
| 3 | **Help Me** | none; raised centre button in brand colour | `C-HELP-01` as a full-screen flow |
| 4 | **Appointments** | count of appointments needing the user's action (e.g. an alternative time proposed) | `C-APP-01` |
| 5 | **Community** | dot for new replies to the user's posts or questions | `C-COMM-01` |

- Tapping the current tab again scrolls to top; a second tap refreshes.
- Each tab keeps its own navigation stack. Switching tabs and back returns to the same place.
- The tab bar hides on full-screen flows (Help Me wizard, review form, composer, camera) and returns on exit.
- The map is **not a tab**. It opens from **Browse on map** (Home and Search Entry), from results, and from profiles (§4.2). The tab bar stays visible on the map screen, and Back returns to where the user came from.

### 2.2 Top app bar (on tab root screens)

| Element | Behaviour |
| :--- | :--- |
| **Vehicle context chip** | Shows nickname and model ("Silver · BMW 320i"). Tap opens `S-SHARED-09` Vehicle Selector. Hidden on Appointments and Community root. |
| **Search icon** | Opens `S-SHARED-01` Search Entry. On Discover the search bar is shown in the page instead. |
| **Notifications bell** | Unread count badge (max "99+"). Opens `S-SHARED-04`. |
| **Avatar** | Opens `S-SHARED-05` Account Menu. Shows a small dot if a consent or profile action is pending (e.g. showcase consent request). |

### 2.3 Global patterns

| Pattern | Rule |
| :--- | :--- |
| **Bottom sheets** | Used for short choices and quick edits (vehicle selector, filters, mileage update, report, share). Swipe down or tap outside to close. If the sheet has unsaved input, closing asks "Discard changes?". |
| **Snackbar with Undo** | Used for reversible actions: unfollow, unsave, remove a photo, mark as read. 5 seconds. |
| **Confirmation dialog** | Used only for irreversible or costly actions: cancel appointment, delete record, mark vehicle sold, delete account, withdraw a consent that removes published content. States the consequence in one sentence. |
| **Pull to refresh** | On every list and detail screen. |
| **Skeleton loading** | Lists and profiles show skeleton cards, not spinners. Spinners only inside buttons. |
| **Inline validation** | Fields validate when the user leaves them, not on every keystroke. Errors appear under the field in plain words and are read by screen readers. |
| **Upload widget** | Shows thumbnail, progress, "Scanning…" state, retry, remove. Uploads continue in the background if the user leaves the screen. Media is EXIF-stripped and scanned server-side (WP13). |
| **Offline** | A thin banner "You're offline. Showing saved data." Garage, vehicle details, appointments and drafts are readable offline. Actions that need the network are queued (notes, mileage) or disabled with a reason (search, send request). |
| **Deep links** | Every notification and every shared link opens the exact screen, with back navigation to the logical parent (e.g. appointment detail → Appointments list). See §6. |
| **AI suggestion element** | Light background, "AI suggestion" label, info icon ("Based on: your description, your vehicle, your service history"), and buttons **Use** / **Edit** / **Dismiss**. If the user turned AI off, these elements are not shown. |
| **Trust badges** | One shared component. Text always visible next to the icon: "Verified Business", "Suspension Specialist", "Verified visit", "Verified record". Tap shows what the badge means and how it was earned (rule-based, MVP Rule 1). |
| **Featured content** | Featured placements are **not active in the MVP** (feature flag `featured.enabled` is off); the slots described in this document are reserved for later. When enabled, they appear only in a separate block with a visible "Featured" label, never inside ranked lists (MVP Rule 2) and **never on the map**. |
| **Directions sheet** | Every **Directions** button opens `S-SHARED-10`, where the user picks an external map app. CarPal shows no route itself. |
| **Query chips** | Under any search box, the app shows how it understood the text (for example "Wheels & tyres · Toyota Corolla") as editable chips. |
| **Review labels** | Visit-verified reviews show "Verified visit". Reviews confirmed by the business and CarPal show "Approved by the business and CarPal". Both count in the score; the second counts for less. There is no separate "unverified" section. |

### 2.4 Shared components used across screens

| Component | Used on | Behaviour |
| :--- | :--- | :--- |
| Vehicle card | Garage, Help Me, selector | Photo, nickname, model/series/year, mileage, status chips (open issue, service due, in repair). |
| Provider result card | Home, Search, Help Me, Saved | Name, distance, rating for the relevant category, badges, one-line match reason, next availability, heart (save). Tap opens profile; "Request" button opens draft. |
| Match explanation card | Help Me, Search, profile (when arrived from a match) | The sentence "Recommended because…" plus expandable structured reasons (evidence, rating, distance, availability, your preference). |
| Status timeline | Appointment detail, issue detail | Vertical steps with time, current step highlighted, notes under each step. |
| Consent row | Request draft, composer, showcase request, privacy | Switch + one-line explanation + "What is shared?" link that opens a preview. |
| Safety banner | Help Me, issue detail, vehicle detail | Red, icon, plain instruction, primary button ("Find urgent help"). |
| Completeness meter | Vehicle detail, add vehicle | Percentage bar + list of missing items, each tappable to fill it. |
| Map pin and pin card | Map View | Pin shape and icon show the type (shop or parts seller, never colour alone). The card is a result card with **Request** or **Ask about part**, **View**, and **Directions**. |

## 4. Screen specifications

### 4.1 Authentication and onboarding

---

#### S-AUTH-01 — Splash / Launch

**Purpose:** start the app, check the session, and send the user to the right place without delay.
**Entry points:** app launch; app return after being killed.

**Layout and elements**

| Element | Details |
| :--- | :--- |
| Logo | Centred, no animation longer than 600 ms. |
| Promise line (first launch only) | "Find the right trusted expert for your exact vehicle and problem — not just the nearest shop." |
| Buttons (first launch only) | **Sign up** (primary), **Log in** (secondary), **Language** switch (FA / EN) at top. Language defaults to the phone language. |

**Interactions**

| User does / system condition | App responds |
| :--- | :--- |
| Valid session | Goes straight to the last tab used, or `C-HOME-01`. No buttons shown. |
| Session valid, onboarding incomplete | Resumes the next onboarding step (`OnboardingProgress.current_step`). |
| No session, not first launch | Opens `S-AUTH-02` Login. |
| Taps Language | Switches UI language and direction immediately, before signup. |
| Opened from a deep link while logged out | Stores the target, shows Login/Sign up, then opens the target after login. |

**States:** loading (logo only, max 2 s before showing a spinner); cannot reach server (shows cached data if a session exists, otherwise "Can't connect. Check your connection." + Retry); unsupported app version (blocking "Update CarPal" screen with store link); UI dictionary CDN unreachable (uses bundled copy silently, Plan §3.1).

**Story:** Ch. 1.

---

#### S-AUTH-02 — Login

**Purpose:** let a returning user in with the least effort.
**Entry points:** splash, "Log in" links, expired session, deep link while logged out.

**Layout and elements**

| Element | Details |
| :--- | :--- |
| Mobile number or email field | One field. Detects which it is. Country code picker for phone, defaults to the device region. Autofill from the OS. |
| Method toggle | **Send me a code** (default for phone) / **Use password**. The last method used is remembered per device. |
| Password field | Shown only for the password method. Show/hide eye icon. OS password manager supported. |
| Continue button | Primary, bottom of screen. Disabled until the field is valid. |
| Forgot password | Link, opens `S-AUTH-08`. |
| Sign up link | "New to CarPal? Sign up". |
| Terms and privacy note | Small text with links. |

**Interactions**

| User does | App responds |
| :--- | :--- |
| Enters phone, chooses code, taps Continue | Sends the code and opens `S-AUTH-07`. |
| Enters password, taps Continue | Signs in. If MFA is on, opens `S-AUTH-07` in MFA mode. |
| Wrong password | Inline error "Mobile number or password is not correct." Does not say which one. Shows remaining attempts after the 3rd failure. |
| Number not registered | "We couldn't find an account with this number." + **Sign up with this number** button that carries the number over. |
| Success on a new device | Opens the target screen, then asks for notification permission with an in-app explainer first (device permission, Story Ch. 3). |

**States:** empty; invalid format; invalid credentials; locked (opens `S-AUTH-09`); suspended (opens `S-AUTH-09`); MFA required; network error.

**UX notes:** keyboard opens automatically on the field; the Continue button sits above the keyboard; the code method avoids password friction on phones.

**Story:** Ch. 3.

---

#### S-AUTH-03 — Sign Up

**Purpose:** create an account with the minimum required information and honest consent choices.
**Entry points:** splash, login screen link, auth wall on a gated action (e.g. "Follow" from a shared link).

**Layout and elements**

| Element | Details |
| :--- | :--- |
| Full name | Required. Not shown publicly (helper text says so). |
| Mobile number or email | Required. Phone stored in E.164. Link to switch: "Use email instead". |
| Password | Required, with strength meter and rule hints shown before typing (min length, etc.). Optional if the user chooses code-only login (product decision; see §8). |
| Country / region | Pre-filled from the device; drives currency, date format, taxonomy region. |
| **Required** checkboxes | "I agree to the Terms" and "I have read the Privacy Policy", each with a link that opens the text in a sheet without leaving the form. |
| **Optional** checkboxes (unticked by default) | "Send me news and offers" (marketing). "Let CarPal use my vehicles and history to tailor suggestions" (AI personalization) with an info icon explaining it in one sentence. |
| Create account button | Primary. Disabled until required fields and boxes are complete. |

**Interactions**

| User does | App responds |
| :--- | :--- |
| Taps Create account | Creates `UserAccount` (`pending_verification`), one `ConsentRecord` per choice with `policy_version`, sends a code, opens `S-AUTH-07`. |
| Number already registered | Inline state "This number already has an account" with **Log in** and **Reset password** buttons. |
| Leaves and returns | Typed values (except password) are kept. |

**States:** validation errors; duplicate account; network error; arrived from an auth wall (a banner says "Create an account to follow Reza Auto Suspension").

**Story:** Ch. 1.

---

#### S-AUTH-07 — Verify Code (new)

**Purpose:** confirm the phone or email, and handle one-time-code login and MFA.
**Entry points:** after sign up, code login, MFA step, changing phone or email in `C-PROF-01`.

**Layout and elements**

| Element | Details |
| :--- | :--- |
| Explanation | "We sent a 6-digit code to +98 912 *** 4567." + **Change** link (back to previous screen). |
| Code input | 6 boxes, numeric keypad, SMS auto-read on Android and code autofill on iOS. Pastes split automatically. |
| Resend | Disabled with a countdown (e.g. 60 s), then enabled. After 3 resends, offers "Get the code by email" if an email exists. |
| Verify button | Auto-submits when 6 digits are entered; the button is there for accessibility. |

**Interactions:** correct code → account becomes `active` (sign up) or session starts (login), then the next step; wrong code → boxes shake, error under the input, input cleared; too many attempts → `S-AUTH-09` timed lock.

**States:** waiting; expired code ("This code expired. We sent a new one."); too many attempts; network error.

**Story:** Ch. 1, Ch. 3.

---

#### S-AUTH-08 — Forgot / Reset Password (new)

**Purpose:** recover access without contacting support.
**Layout and elements:** step 1 phone/email field → `S-AUTH-07` code → step 2 new password + confirm, strength meter → success message "Password changed. Other devices have been signed out." with **Continue**.
**Interactions:** unknown number shows the same neutral message as a known one ("If this number has an account, we sent a code") to avoid account discovery.
**States:** code expired; weak password; network error.

---

#### S-AUTH-09 — Account Locked / Suspended (new)

**Purpose:** explain why the user cannot log in and what to do next.

| Variant | Content | Actions |
| :--- | :--- | :--- |
| Timed lock (too many attempts) | "For your security, sign-in is paused for 15 minutes." Live countdown. | **Reset password**, **Contact support**. |
| Suspended by moderation | Plain reason category (e.g. "fake reviews"), date, and what is still accessible (data export). | **Appeal this decision** (opens a form: reason text 10–2000 chars, optional attachment; creates a `Dispute` of type `moderation_appeal`), **Download my data**, **Contact support**. |
| Deactivated by user | "Your account is deactivated." | **Reactivate** (sends a code). |

**Story:** Ch. 3 other paths.

#### S-AUTH-04 — Role Selection

**Purpose:** record the user's main intent and route to the right onboarding, without locking them in.

**Layout and elements**

| Element | Details |
| :--- | :--- |
| Title | "How will you mainly use CarPal?" |
| Four option cards (single choice) | **I own or manage personal vehicles** (pre-selected highlight) · **I manage a company fleet** · **I run a repair or service business** · **I sell car parts**. Each has an icon and one line of description. |
| Note | "You can join or create a business later with the same account." |
| Continue button | Primary. |

**Interactions:** individual → `S-AUTH-05` then `C-ONB-01`. Business choices → on mobile, a screen explains that business tools open in the web portal, offers **Open on web** / **Email me the link**, and lets the user continue as an individual meanwhile. User already invited to an organization → that organization is shown at the top as "You've been invited to join…".

**Story:** Ch. 1.

#### S-AUTH-05 — Consent and Permissions

**Purpose:** explain each permission in plain language and ask for it at a sensible moment.

**Layout and elements:** a single scrollable screen with one card per permission. Each card has an icon, title, one-sentence reason, and its own button. A sticky **Continue** button at the bottom works whatever the user chose.

| Card | Reason text | Button | Result |
| :--- | :--- | :--- | :--- |
| Location | "To find help near you and to open the map where you are." | **Allow while using the app** | Triggers the OS prompt. `location_usage` consent. |
| Notifications | "Appointment updates and reminders." | **Allow notifications** | OS prompt; registers `PushDeviceToken`. |
| Photos and camera | "To attach pictures of problems and documents." | **Allow later** (default) | Asked again when the user first taps camera/gallery. |
| Review invitations | "CarPal may ask you to review a shop after a visit." | Switch, on by default only for in-app; channel choice in `C-PROF-04` | `review_invitations` consent. |

**Interactions:** declining location shows the note "We'll ask for a city when you search or open the map." Nothing is blocked. Already-granted OS permissions show a green check instead of a button.

**States:** all accepted; partially accepted; OS permission permanently denied (the card shows **Open settings**).

**Story:** Ch. 1.

#### C-ONB-01 — Add First Vehicle

**Purpose:** create the first vehicle so that every later screen is vehicle-aware.
**Entry points:** onboarding after `S-AUTH-05`; Home empty state; Help Me with no vehicle.

**Layout and elements**

| Element | Details |
| :--- | :--- |
| Progress | "Step 1 of 2" (step 2 is `C-ONB-02`). |
| Method tabs | **VIN** (default) · **Choose from list**. |
| VIN field | 17 characters, uppercase, letters I/O/Q rejected with a hint. **Scan** icon opens the camera to read the VIN from the registration card or windscreen. "Where do I find my VIN?" link opens an illustrated sheet. |
| Decoded result card | Brand, model, series, year, fuel, transmission, engine. Each field has an edit icon. A small "From VIN" tag marks decoded fields. |
| List method | Brand (searchable list with logos) → Model → Series/generation (with year ranges, e.g. "E90 · 2005–2012") → Year. "I don't know the series" option allowed. |
| Mileage | Numeric with unit (km/mi from region). Optional but suggested. |
| Nickname | Optional, placeholder "e.g. Silver". |
| Photo | Optional; camera or gallery. |
| Completeness meter | Updates live; lists what is missing. |
| Buttons | **Save vehicle** (primary), **Skip for now** (text link). |

**Interactions**

| User does | App responds |
| :--- | :--- |
| Enters full VIN | Decodes within 2 s; shows the result card. |
| VIN year conflicts with typed year | AI suggestion: "This VIN suggests 2011; you entered 2012." Buttons **Use 2011** / **Keep 2012**. |
| Decoder unavailable or partial VIN | Message "We couldn't read this VIN. Choose your car from the list instead." Switches to list method with any known fields kept. AI helper may suggest model/series as an AI suggestion. |
| Taps Save | Creates `Vehicle` (`active`), sets it as primary, goes to `C-ONB-02`. |
| Taps Skip | Goes to `C-HOME-01` with the "Add your vehicle" card at the top. |

**States:** VIN decode failed; manual mode; duplicate vehicle (same VIN already in this account: "This vehicle is already in your garage"); vehicle limit reached (cannot happen at onboarding, but handled by `C-PLAN-01`); success.

**UX notes:** VIN scan saves typing 17 characters; list method shows the most common brands for the region first.

**Story:** Ch. 2.

#### C-ONB-02 — First Problem (Optional)

**Purpose:** show value at once if the user already has a problem.

#### C-REV-01 — Write Review

**Purpose:** collect a specific, honest, structured review in under two minutes.
**Entry points:** review invitation notification or email link, a completed appointment, a service record, and the **Write a review** button on a provider profile.

**Two ways a review is confirmed**

| | Path 1: visit-based | Path 2: approval-based |
| :--- | :--- | :--- |
| When | The user had an appointment with the shop that was confirmed and took place, and writes within 7 days of the invitation. | There is no appointment, or the 7-day window has passed (the appointment is then attached as evidence). |
| What happens | Verified automatically after the automatic safety and abuse checks. The shop does not approve it and cannot block it. | Hidden, "Waiting for approval". The shop has 7 days to confirm the user was its customer (silence means no objection). Then a CarPal reviewer approves. |
| Shown as | **Verified visit** | **Approved by the business and CarPal** |
| Score weight | Full | Lower (Doc 54) |

If the shop rejects Path 2, the review goes to dispute handling; the user can add evidence and a CarPal reviewer decides.

**Layout and elements**

| Element | Details |
| :--- | :--- |
| Context header | Path 1: "Verified visit · BMW 3 Series · Suspension · Reza Auto Suspension". Path 2: "No appointment — the shop and CarPal will check this review before it is published." |
| Overall rating | 5 large stars, required. |
| Sub-ratings | Work quality, Communication, Timeliness, Price accuracy, Cleanliness (each 1–5, optional but encouraged); Would you return? Yes / No. |
| Review text | 10–5000 chars. Prompt "What was done, how was the communication, did the price match?" Live helper (AI): "Mention what was fixed" style nudges. |
| Privacy check | Inline warning when the text appears to contain a plate number, phone number or full name: "This looks like a licence plate. Remove it?" **Remove** / **Keep**. |
| Tags | AI-suggested tags as chips (e.g. "explained clearly", "fair price", "fixed first time"); the user keeps or removes each; only kept tags are published. |
| Photos | Optional, with redaction notice. |
| Display note | "Shown as Sara M. Your phone and full name are never shown." |
| Submit | Sticky. Path 2 reads **Send for approval**. |

**Interactions:** submit → `C-REV-02`; abusive language detected → suggestion to rephrase (not blocking); duplicate review for the same visit → opens the existing review in edit mode.
**Invitation link:** the email link opens this screen for that one visit. If the user is not signed in, `S-AUTH-07` asks for a one-time code first, so a forwarded link is not enough. The link works once and expires 7 days after it was sent; an expired or used link shows a clear message, with **Write a review from the profile** (Path 2) or **Open your review**.
**States:** no confirmed appointment (Path 2 mode); window passed (Path 2 with the appointment attached); link expired or already used; draft saved; moderation notice.

## 7. Accessibility and localisation checklist

- Screen reader labels on all icons, badges and chart bars; badges are read as text ("Verified Business").
- Urgency and status use colour **and** icon **and** words.
- Minimum contrast 4.5:1 for text; tap targets ≥ 48 dp.
- Dynamic type to 200% without clipped buttons; long Persian words wrap.
- RTL: tab order, swipe directions, sliders (before/after slider handle direction follows layout), progress steps and chevrons mirror. Phone numbers, VINs and plates stay LTR inside RTL text.
- Dates: Jalali in FA, Gregorian in EN; times in 24 h for FA.
- Numbers: Persian digits on display, Latin digits accepted in inputs.

## 8. Open points (for WP0)

1. **New screen IDs.** This document adds `S-AUTH-07`, `S-AUTH-08`, `S-AUTH-09`, `S-SHARED-08`, `S-SHARED-09`, `C-ONB-03`, `C-INV-03`, `C-GARAGE-06`–`09`, `C-APP-04`, `C-REV-03`, `C-REV-04`, `C-COMM-06`, `C-PROF-04`–`09`, `S-SHARED-10`. They should be added to Doc 90.
2. **Auth ID conflict.** Doc 56 uses `S-AUTH-05` for verification and `S-AUTH-06` for consent; Doc 90 and Story 10 use `S-AUTH-05` for consent. This document keeps Doc 90 and gives verification the new ID `S-AUTH-07`.
3. **Onboarding ID conflict.** Doc 56 uses `C-ONB-02` for Interests; Doc 90 and Story 10 use it for First Problem. This document keeps Doc 90 and adds Interests as `C-ONB-03`.
4. **Social ID aliases.** Doc 56 uses `C-FEED-01`, `C-POST-01/02`, `C-COMPOSER-01–03`, `C-NOTIF-01`. This document uses Doc 90's `C-COMM-*` and `S-SHARED-04` and treats the Doc 56 IDs as aliases. One set should be chosen.
5. **Password at signup.** Story 10 has a password at signup but code-only login later. Decide whether a password is required or optional for phone accounts.
6. **Business roles on mobile.** This document assumes provider, vendor and fleet manager tools are web-only in MVP (WP20), and the mobile app links out. Fleet driver views on mobile (WP19) are not covered here.
7. **Notes thread on appointments.** `C-APP-02` uses `AppointmentNote` as a simple message thread. Confirm that this is not "live chat" (deferred).
8. **Late cancellation rules.** The notice period and what the shop sees are not defined.
9. **Navigation app links.** The app list per region (pilot country and USA/Europe) and the exact link format for each app must be verified before `S-SHARED-10` is built.
10. **Featured placements.** Not active in the MVP. The strips on Home, Search Results and Help Me are reserved slots behind a flag. Featured placements are never shown on the map.
11. **`C-HELP-07` / `C-HELP-08` naming.** These screens are used from every entry point but keep their Doc 55 IDs. A neutral ID (for example `C-REQ-01/02`) could be introduced when Doc 90 and Doc 55 are updated.
12. **Map tile coverage and offline use.** Only the pilot city must be covered at first. Caching tiles for the last viewed area is a Should; offline map downloads are later.
13. **Review labels and weight.** The labels "Verified visit" and "Approved by the business and CarPal", and the lower weight of approval-based reviews, must be reflected in Doc 52 and Doc 54.
14. **Trusted users.** After the MVP, trusted users (more than 100 helpful votes and an accepted invitation link) can act as social reviewers. No consumer screen is designed for the invitation yet.
