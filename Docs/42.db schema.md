# 1. Platform and Installation

| Item | Value |
|---|---|
| Engine | PostgreSQL 16 or later (uses `NULLS NOT DISTINCT`, `\if` in psql) |
| Extensions | `vector` (pgvector ≥ 0.5, HNSW) — required; `pg_trgm` — optional, trigram indexes are skipped without it |
| Extension schema | `ext` (nothing is installed in `public`) |
| Databases | `carpal` (system of record) and `carpal_analytics` (product events) |
| Encoding | UTF-8; locale from `-v db_locale` (default `C`; use `C.UTF-8` or ICU where available) |
| Install | `psql -X -d postgres -f "42.db_setup.sql" -v env=dev -v admin_email=… -v <role>_password=…` as a superuser |
| Re-run | Refused: the script stops if `carpal` exists. Later changes are numbered migrations in `database/migrations/`. |
| Secrets | No password is in the script. Missing `-v <role>_password` → the role exists without a password until the secret manager sets one. |

Verified on 2026-10-09 by a clean install on PostgreSQL 16.2 + pgvector, followed by role-based tests (§11).

# 3. Roles

| Role | Login | Used by | Rights |
|---|---|---|---|
| `carpal_owner` | no | — | Owns every object. Bypasses RLS as table owner. |
| `carpal_migrator` | yes | CI migrations | Member of `carpal_owner`; runs `SET ROLE carpal_owner` for DDL |
| `carpal_app_base` | no | group | Schema `USAGE`, `EXECUTE` on module functions |
| `carpal_ctx_system` | no | marker | Allows the `system` RLS context |
| `carpal_ctx_staff` | no | marker | Allows the `staff` RLS context |
| `carpal_auth` | yes | Auth server (D1) | `identity` read/write; audit and outbox insert; system context |
| `carpal_api` | yes | Public API (D2) | SELECT/INSERT/UPDATE on module tables, always under RLS; no DELETE except `community.reactions`; audit insert only |
| `carpal_admin_api` | yes | Admin API (D3) | As API, plus audit read; staff context |
| `carpal_worker` | yes | Workers (D5) | All DML incl. DELETE (retention, anonymization); system context; partition maintenance |
| `carpal_ai` | yes | MCP gateway, AI orchestration | `ai_mcp` read/write, outbox/audit insert, flags read; system context |
| `carpal_readonly` | yes | Reporting | Taxonomy and plans only; read-only transactions |
| `carpal_analytics_writer` / `_reader` | yes | Analytics pipeline / BI | `carpal_analytics` only |

Session limits per role (statement, lock and idle-in-transaction timeouts) and `search_path = pg_catalog, core, ext` are set per database. Nobody else can connect (`REVOKE ALL ON DATABASE … FROM PUBLIC`), and `public` is locked.

Append-only tables (`vehicle_status_history`, `appointment_status_history`, `moderation_actions`, `audit_logs`, `mcp_access_logs`, `ai_evaluation_records`) have no UPDATE/DELETE/TRUNCATE grant for any application role and a trigger that refuses changes.

# 4. Conventions

| Topic | Rule |
|---|---|
| Names | Schemas = modules; tables = plural snake_case of the 52 entity (`InventoryItem` → `inventory.inventory_items`); columns = 52 field names |
| Common columns (52 §2.1, §2.3) | `id uuid` (UUIDv7, `core.uuid_v7()`), `version`, `created_at`, `created_by`, `updated_at`, `updated_by`, `deleted_at`, `deletion_reason`. Trigger `zz_touch` sets `updated_at`, `updated_by`, increments `version` and freezes `id`/`created_*`. Append-only tables carry only `id` and their timestamp. |
| Enums | `text` + `CHECK`. Shared 52 §3 enums are domains in `core` (`core.review_status`, `core.urgency_level`, …); entity enums are inline checks. Adding a value is a one-line migration (40 TR-3). |
| Reserved values | `*_future` values stay in the enum but a named constraint `…_mvp_reserved` rejects them in the MVP (drop the constraint to activate) |
| Other domains | `core.email` (lower case), `core.phone` (E.164), `core.currency`, `core.country`, `core.locale`, `core.url` (https), `core.slug`, `core.tz`, `core.lat`/`core.lng` (WGS84, 6 decimals), `core.amount` (`numeric(12,2) ≥ 0`), `core.score` (0–100), `core.rating` (1–5), `core.km`, `core.hash` (32-byte HMAC/SHA-256) |
| Translations (52 §2.4) | `jsonb` domain `core.translations` (`{"en": "…", "fa": "…"}`); per-column `core.translations_ok(col, max_len)`; taxonomy labels require `en` and `fa`; GIN (`jsonb_path_ops`) where searched. `core.l10n(map, locale)` applies the read rule. |
| Money | Amount + currency columns, checked together |
| Text normalization | `core.normalize_search_text()` (NFC, Arabic ي/ى/ك → Persian ی/ی/ک, Latin digits, ZWNJ → space, lower case) — used for `match_sessions.query_normalized` and `taxonomy_synonyms.term_normalized` |
| Polymorphic references | `*_type` + `*_id` with a `CHECK` on the allowed types |
| Lists | `uuid[]`/`text[]` with cardinality checks and `<@` value sets; structured values as `jsonb` with type checks |
| Partitioning | `analytics.audit_logs`, `ai_mcp.mcp_access_logs`, `events.analytics_events`: monthly range partitions + a default partition; `core.ensure_monthly_partitions()` creates 3 months ahead (scheduler, daily) |
| Geo | No PostGIS in the MVP; geo search runs in Elasticsearch. `core.distance_m()` for the pin-versus-address check. |

# 5. Request Context and Row-Level Security

## 5.1 Context

Every application transaction starts with

```sql
SELECT core.set_context(actor_type, user_id, org_id, role, request_id, anon_key);
```

| Setting | Meaning | Read by |
|---|---|---|
| `actor_type` | `anonymous`, `user`, `staff`, `system` | `core.actor_type()`, `core.is_system()`, `core.is_staff()` |
| `user_id` | Authenticated user (staff user on the admin plane) | `core.me()` |
| `org_id` | Organization of the request path, already authorized by the API (40 SEC-AZ-2) | `core.my_org()` |
| `role` | Caller's role there (audit only) | — |
| `request_id` | Correlation ID | outbox, audit |
| `anon_key` | Hash of the anonymous token's device key | `core.my_anon_key()` |

`system` is accepted only for roles in `carpal_ctx_system` (auth, workers, AI); `staff` only for `carpal_admin_api`. The API role asking for either is refused (tested). Settings are transaction-local.

## 5.2 Policies

RLS is enabled on every module table. Each table has `system_all` and `staff_all` policies plus tenant policies:

| Tenancy class (50 §3) | Policy pattern | Examples |
|---|---|---|
| user-private | `user_id = core.me()` | preferences, consents, DSRs, follows, favorites, notifications, triage sessions |
| org-private | `organization_id = core.my_org()` (or `provider_/vendor_/fleet_organization_id`) | locations, profiles, capabilities, job logs, customer notes, inventory, fleet tables, availability |
| owned by user **or** organization | `owner_type`/`owner_id` against `me()`/`my_org()` | vehicles, media assets, subscriptions (read) |
| child rows | visible when the parent is visible (`EXISTS` on the parent, itself under RLS) | vehicle children, appointment children, fitment, inquiry messages, match results, evidence |
| party-based | any party of the record | appointments (requester user, requester fleet, provider), stock inquiries (vendor, requester), consent requests, review requests (business, invitee) |
| public | read-only, published/approved rows only | active organizations and locations, published profiles and portfolio, verified certifications, public capabilities (≥ low evidence), published reviews and responses, active plans, taxonomy, active availability, public trade-free inventory |
| trade | `trade_only` items only for members of an organization with an approved trade account | `inventory.inventory_items` |
| platform-internal | system/staff only | moderation, flags (read allowed), four-eyes, assist sessions, retention, MCP registry and logs, pseudonym keys |

Special rules:

- **Organization creation:** the application generates the ID, sets `org_id` to it, then inserts; the insert policy accepts only `status = 'draft'` rows of the current context, and a subscription insert only for the audience's default plan (paid plans are assigned by staff).
- **Internal appointment notes** are visible to the provider only; requesters see `customer_visible` notes.
- **Trust signals** `risk_fraud_flag` and `review_authenticity_score` never reach the organization.
- **Column-level secrecy** (exact coordinates of approximate locations, `price_trade`, internal notes, AI review flags, `vehicle_id` on questions) is enforced by the API's allowlist projections (40 SEC-AZ-5, SEC-OUT-1); RLS is the row-level second wall (40 SEC-AZ-3).

## 5.3 Definer functions (controlled cross-tenant access)

All are `SECURITY DEFINER` with `search_path = pg_catalog`, return only minimal columns, and are granted to the application roles only.

| Function | Purpose |
|---|---|
| `identity.user_cards(ids)` | Display name and status for other modules (requester names, review authors); never contact data |
| `organization.org_cards(ids)` | Name, type, slug, status, verification, trust score |
| `vehicle.vehicle_cards(ids)` | Brand/model/series/year/engine/fuel/nickname for providers and vendors; never VIN, plate, notes or owner |
| `media.delivery_info(id)` | Storage keys of a clean, active asset; called only after the owning module authorized the viewer |
| `appointment.check_in_by_token(hash)` | Anonymous `ci` link check-in: atomic, ±2 h window, emits `appointment.status_changed` |
| `trust.open_invitation(hash)` | Anonymous `ri` link open: records `opened_at`, emits `review.invitation.opened`, raises `LINK_EXPIRED`/`LINK_USED` |
| `identity.accept_invitation(hash)` | `mi` link: signed-in user's verified email must equal the invited email (40 SEC-LT-5) |
| `core.ensure_monthly_partitions(table, n)` | Creates partitions for the two allowlisted log tables (worker only) |
| `core.publish_event(…)`, `analytics.write_audit(…)` | Write-only helpers: the application roles may only INSERT into the outbox and the audit log, and the `RETURNING` of the new id would otherwise need SELECT on those tables (fixed in backend S2) |

Link-token errors use SQLSTATEs `P0410` (expired), `P0411` (used), `P0403` (recipient mismatch), `P0409` (invalid transition) so the API maps them to 40 §4.4 codes.

# 6. Integrity Rules Enforced in the Database

| Rule (source) | Mechanism |
|---|---|
| One active role per user per organization; one implicit `individual` role; platform roles without organization (52 §4) | partial unique indexes, `role_memberships_org_rule` |
| New account gets preferences (Jalali/Persian digits for `fa`) and the individual role | trigger `user_accounts_bootstrap` |
| Consent records immutable except one withdrawal | trigger `consent_records_immutable` |
| One primary active location; public point exact or rounded to 0.01°; moving the pin clears verification (40 SEC-OUT-4) | partial unique index, trigger `organization_locations_public_point` |
| AI-suggested catalog/coverage/capability rows reference their insight; badge eligibility only at strong evidence | checks |
| Capability evidence: AI links start pending; counted evidence immutable; revoked stays revoked (54 §2, §9) | trigger `provider_capability_evidence_immutable` |
| Portfolio published only with approved moderation and consent | `portfolio_items_publish_rule` |
| Plan audience matches subscriber; one active/trial subscription per subscriber | trigger, partial unique index |
| Taxonomy parent rules, no cycles, type-specific attributes, EN+FA labels; mapping node types match | triggers `taxonomy_nodes_rules`, `taxonomy_mappings_types`, checks |
| VIN unique per owner (non-archived); ciphertext/hash/last4 together | partial unique index, check |
| Vehicle status changes recorded; latest mileage mirrored; lower reading flagged | triggers |
| Service record source rules; one record per appointment | checks, partial unique index |
| Inquiry vendor = item vendor; transitions per side (40 §13.1); `closed_at`, `first_response_at` set | trigger `stock_inquiries_rules` |
| One open inquiry per user and item | partial unique index |
| Match results never sponsored in the MVP; reasons non-empty; unique rank per session | checks, unique |
| Review paths: Path 1 statuses ⇔ visit-based; Path 2 needs business step + reviewer; Path 2 publishes only when approved and business `confirmed`/`no_response` (or upheld dispute); verified status needs its context; one review per visit | named checks `reviews_*`, partial unique indexes |
| Invitation: exactly one visit, expires `sent_at + 7 days`, one open invitation per visit, job-log invitations count as business confirmation | checks, partial unique indexes |
| Sub-rating dimension matches provider/vendor; response only by the subject; one published and one draft response | triggers, partial unique indexes |
| Appointment transitions per side (52 §12, 40 §16.1); `requested` needs a time window (checked at commit); status history written automatically | triggers `appointments_status`, `appointments_history`, constraint trigger `appointments_requested_window` |
| Capacity at confirmation, serialized per location | `appointment.capacity_available()` with advisory lock |
| Pre-visit history only with consent; no triage insight when triage was not provided | checks |
| One active driver assignment per vehicle; fleet approval never self-approved | partial unique index, `fleet_approvals_no_self_approval` |
| Accepted answer belongs to its question | composite foreign key |
| Reaction type matches target; one per user, target and type | checks, unique |
| Infected media quarantined; documents encrypted; public media conditions | checks, generated `publicly_servable` |
| Four-eyes: decider ≠ requester; assist session ≤ 4 h, one active per organization | checks, partial unique index |
| Staff PII reads carry a purpose | `audit_logs` check (`pii.read` ⇒ `access_purpose`) |
| AI approvals never self-approved; capability/badge insights carry evidence; MCP client lists use catalog key formats | checks |
| Entitlement checks serialized per subscriber (40 SEC-AZ-9) | `billing.lock_subscriber()` + `billing.effective_entitlement()` |

Rules that need another module's data (vehicle limits vs. plan, fleet approval required, consent before sharing, organization type vs. plan audience) are enforced by the application inside the same transaction.

# 7. Events and Jobs

- `core.publish_event(type, aggregate_type, aggregate_id, payload)` writes the outbox row in the caller's transaction and fires `pg_notify('carpal_outbox')`; the relay worker publishes to NATS JetStream (50 §20).
- `core.background_jobs` is the durable record of every `202 Job`; owners and organization members read their own jobs.
- `analytics.write_audit(action, entity_type, entity_id, reason, …)` writes the `AUD` entry with actor, organization and request ID from the context.

# 10. Operations

| Task | How |
|---|---|
| Partitions | Scheduler (W15) runs `core.ensure_monthly_partitions(…, 3)` and `events.ensure_monthly_partitions(3)` daily |
| Retention | Workers apply `admin.data_retention_policies`; log tables are trimmed by dropping old partitions |
| Migrations | Numbered SQL files run by `carpal_migrator` with `SET ROLE carpal_owner`; default privileges grant new tables to the application roles |
| Backups | Both databases; restore drill in WP1 |
| Passwords | Set by the secret manager (`ALTER ROLE … PASSWORD`), rotated per policy |
| Time zones | Production servers need the IANA tz database (capacity checks use location time zones) |

# 11. Verification

Run on PostgreSQL 16.2 + pgvector, clean install, then tests connected as the real roles:

- Install: exit code 0, no errors (one expected warning where `pg_trgm` is not installed).
- API role: cannot take `system`/`staff` context; cannot self-assign a paid plan; cannot create another tenant's organization or vehicle; another user cannot see a draft organization, a vehicle or its mileage; vehicle cards work across tenants without exposing VIN.
- Business rules: draft → confirmed by the requester refused; `requested` without a time window refused at commit; status history written with sides and append-only; internal notes hidden from the requester; Path 2 publish without approvals refused; `appointment_verified` without an appointment refused; second review for the same visit refused.
- Anonymous: sees plans and taxonomy, no users, no unpublished reviews; audit log and pseudonym keys not readable.
- Functions: capacity check refuses an overlapping slot at capacity; check-in by link works and unknown tokens raise `LINK_EXPIRED`; requester cannot reserve an inquiry; cancel sets `closed_at`.
- Worker/staff: audit log cannot be deleted; reserved MCP client type, sponsored results, orphan tasks and taxonomy labels without Persian refused; staff sees all organizations; four-eyes self-approval refused.

Contract and RLS tests in CI (pgTAP, 41 backend plan §8) should extend this set.
